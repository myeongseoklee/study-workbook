# 03. 탐색 공간을 설계한다 — 사람이 문제를 짚고 AI가 뒤진다

## 학습 목표

"인사이트 찾아줘"가 왜 실패하는지 확률의 문제로 설명하고, 그 실패를 막는 세 가지 지정(문제 지정 · 결론 유보 · 다양성 강제)을 프롬프트에 실제로 넣을 수 있게 된다.

## 선수 지식

- [02장](02-three-inferences.md)의 세 추론 구분. 이 장은 **귀추 구간을 다루는 방법**이다

## 핵심 원리 (WHY)

### 수렴은 버그가 아니라 훈련 목표다

언어 모델은 다음에 올 확률이 높은 것을 내놓도록 훈련되었다. 그래서 "왜 이런 일이 벌어졌을까?"라고 열린 질문을 던지면, **확률이 가장 높은 설명 쪽으로 답이 모인다.** 다섯 개를 달라고 해도 서로 비슷한 다섯 개가 온다.

이것은 고장이 아니다. 훈련 목표가 그렇게 시켰다. 그러므로 고치려면 프롬프트로 **반대 압력**을 걸어야 한다.

압력의 방향은 셋이다.

| 압력 | 무엇을 막는가 |
|---|---|
| **문제를 지정한다** | 탐색 공간이 너무 넓어서 평균적인 답으로 내려앉는 것 |
| **결론을 유보시킨다** | 관측을 모으는 도중에 설명이 붙어 관측이 오염되는 것 |
| **다양성을 강제한다** | 같은 메커니즘의 변형이 서로 다른 가설인 척하는 것 |

### ① 문제를 지정한다 — 사람은 짚고 AI는 뒤진다

같은 대상을 두고 두 프롬프트를 비교해 보자.

> "엔비디아 분석해줘"

평균적으로 그럴듯한 분석이 나온다. 그럴듯하다는 것이 문제다. 이미 아는 것과 겹친다.

> "공장이 미친듯이 돌고, 못 만들어서 못 파는데 주가는 왜 −13%지?"

여기서 달라진 것은 정보량이 아니라 **탐색 공간의 모양**이다. 첫 번째는 "엔비디아에 관해 말할 수 있는 것 전부"에서 평균을 뽑는다. 두 번째는 "수요는 강한데 주가는 빠지는 상황을 설명하는 것들"이라는 좁고 이상한 영역만 뒤진다.

분업의 기본형이 여기서 나온다.

```
사람 ──▶ 문제를 짚는다
AI   ──▶ 그 문제 공간을 뒤진다
```

사람은 어디가 이상한지를 정하고, AI는 그 안을 전부 훑는다.

이 분업이 서면 프롬프트를 길게 쓸 필요가 없다. **좌표를 정확히 주는 것이 길게 쓰는 것보다 낫다.**

### ② 결론을 유보시킨다 — 이상한 후보를 대량 생산한다

"인사이트 찾아줘"라고 하면 AI가 관측과 설명을 한 번에 한다. 그러면 설명이 먼저 정해지고 관측이 거기 맞춰 골라진다.

그래서 두 단계를 분리한다. 먼저 **설명 없는 이상 후보만** 대량으로 뽑는다.

> 결론을 내리지 마라. 이 자료들 안에서 서로 동시에 사실이기 어려워 보이거나, 일반적인 기대와 다른 방향인 사실만 20개 찾아라.
> 그리고 각 항목을 — 예상했던 것 / 실제 관측된 것 / 둘 사이의 차이 — 로 적어라.
> 원인은 아직 설명하지 마라.

세 칸(예상 / 관측 / 차이)이 이 프롬프트의 핵심이다. **차이를 명시적으로 적게 만들면 "이상함"이 주관이 아니라 기록이 된다.** 나중에 사람이 고를 때 비교할 근거가 남는다.

"원인은 아직 설명하지 마라"를 빼면 어떻게 되는가. AI가 각 항목에 곧바로 설명을 붙이고, **가장 흔한 설명으로 수렴한다.** 그러면 20개를 뽑은 의미가 사라진다. 서로 다른 관측 20개가 아니라 같은 이야기 20번이 되기 때문이다.

### ③ 다양성을 강제한다 — 영역을 지정하고 변형을 금지한다

관측을 골랐으면 이제 설명 가설을 만들 차례다. 여기서도 그냥 시키면 수렴한다. 그래서 두 가지 제약을 건다.

> 아래 이상현상을 설명할 가설을 15개 만들어라.
> 단, **앞의 가설과 같은 방식이나 메커니즘의 변형은 새로운 가설로 세지 마라.**
> 최소한 다음 영역을 하나씩 포함하라 — 회계 / 재무 / 고객행동 / 경쟁 / 물리적 제약 / 시간차 / 규제 / 조직 인센티브 / 공급망 / 시장심리.
> 서로 동시에 참일 필요도 없다. 지금은 설명할 수 있는 가능성을 넓히는 작업이다.

세 제약이 각기 다른 일을 한다.

| 제약 | 막는 것 |
|---|---|
| 메커니즘 변형 금지 | 개수만 채우는 것. "환율 때문" "환율 변동성 때문" "환율 헤지 실패 때문"은 하나다 |
| 영역 목록 지정 | 익숙한 영역(대개 재무·시장심리)에만 몰리는 것 |
| 동시 참 불필요 | 서로 모순되는 가설을 미리 지워 버리는 것. 지금은 넓히는 단계다 |

세 번째가 특히 자주 빠진다. 이 문장이 없으면 AI가 **일관된 이야기 하나**를 만들려고 하고, 그러면 후보가 아니라 답이 온다.

## 필수 지식 (HOW)

### 세 프롬프트의 위치

```
관측 자료
│
▼
① 문제 지정 : 사람이 좌표를 찍는다
│
▼
② 이상 후보 20개 : 설명 금지, 예상/관측/차이 세 칸
│
▼
(사람이 진짜 이상한 것을 고른다)
│
▼
③ 가설 15개 : 메커니즘 중복 금지 + 영역 커버리지
│
▼
(사람이 셋을 고른다)
```

②와 ③ 사이, ③ 다음에 각각 사람이 한 번씩 개입한다. 그 두 개입이 [04장](04-what-only-humans-pick.md)의 주제다.

### 영역 목록은 고정된 것이 아니다

원문이 든 열 개 영역은 기업 분석용이다. 다른 분야에서는 다른 목록을 써야 한다. 목록을 고를 때의 기준은 **서로 독립적인 인과 층위인가**다.

| 분야 | 쓸 만한 영역 목록의 예 |
|---|---|
| 기업·투자 분석 | 회계 / 재무 / 고객행동 / 경쟁 / 물리적 제약 / 시간차 / 규제 / 조직 인센티브 / 공급망 / 시장심리 |
| 서비스 장애 조사 | 코드 / 설정 / 용량 / 네트워크 / 의존 서비스 / 데이터 / 배포 절차 / 사람의 조작 / 시간대·부하 패턴 |
| 지표 하락 원인 | 유입 / 전환 / 이탈 / 측정 자체의 변화 / 경쟁 / 계절성 / 정책 변경 |

"측정 자체의 변화"처럼 **문제를 문제로 보게 만든 관측이 사실은 계측 오류일 가능성**을 목록에 넣어 두는 것이 값을 한다. 이 영역은 사람이 잘 안 떠올린다.

### ⚠️ 암기 필수

- [ ] **수렴은 고장이 아니라 훈련 목표다** — 확률이 높은 것을 내놓도록 훈련됐으므로, 다양성이 필요하면 프롬프트로 반대 압력을 걸어야 한다
- [ ] **관측 단계에서 설명을 금지한다** — 설명을 같이 시키면 가장 흔한 설명으로 수렴하고, 관측이 그 설명에 맞춰 골라진다. 그래서 "원인은 아직 설명하지 마라"가 프롬프트에 들어간다
- [ ] **가설 다양성을 강제하는 세 제약: 메커니즘 변형 금지 · 영역 커버리지 지정 · 동시 참 불필요** — 셋 중 마지막이 가장 자주 빠지고, 빠지면 후보가 아니라 하나의 일관된 답이 온다

## 하네스 설계로 옮기면

후보를 생성하는 서브에이전트를 여러 개 띄울 때, **같은 프롬프트로 N개를 띄우면 N개가 비슷하게 수렴한다.** 다양성은 개수가 아니라 **렌즈의 차이**에서 나온다. 각 에이전트에 서로 다른 영역을 배정하는 것이 여기 ③번 제약의 하네스 판이다.
