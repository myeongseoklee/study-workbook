# 90. 암기 필수 카드

검색 없이 즉답해야 하는 것만 모았다. 설계·판단을 가르는 경계, 불변 트레이드오프, 진단 신호에 한정한다.

## 정의 — 이 한 문장을 못 대면 나머지가 흔들린다

- [ ] **워크플로우 vs 에이전트의 유일한 구분선:** 제어 흐름을 **코드**가 잡으면 워크플로우, **모델**이 잡으면 에이전트. (그 외 기준은 다 부차적)
- [ ] **에이전트 = 모델의 제어권 확장.** 세션·서브에이전트·골·도구·훅은 전부 "모델에게 얼마나 제어권을 넘기는가"의 문제로 수렴한다.
- [ ] **서브에이전트 = 모델이 도구로 생성한 세션.** 세션(사람이 연 것)과 서브에이전트(모델이 연 것)는 둘 다 실체가 세션이다.
- [ ] **에이전트 루프 3요소:** 세션(턴을 담는 그릇) ⊃ 턴(요청→최종응답) ⊃ 이터레이션(턴 안의 연속 모델 호출).
- [ ] **세션의 정체 = 모델이 들고 있는 KV 캐시의 식별 ID.** 캐시 ID가 다르면 다른 세션. 그래서 병렬 세션 수 = 캐시 세트 수 = 메모리 비용. `#2`
- [ ] **식별 ID는 세 층으로 분리된다:** ① KV 캐시(프리픽스 유지·영속화 키) ② 컨텍스트 구조체 접근 권한 ③ 도구·메시지큐 결과 보고 대상. 생명주기가 서로 달라 합칠 수 없다. `#2`
- [ ] **컨텍스트 = 기반 컨텍스트(세션 시작 시 계산 후 고정) + 턴 로그(단조 증가 불변 리스트).** `#2`
- [ ] **컴팩트 레코드 = 스냅샷 구분점.** 모델 입력은 **마지막 컴팩트 아래로만** 구성한다(전체 로그에는 여러 개 존재). `#2`
- [ ] **3강의 화면은 정답이 아니라 참조 구현이다.** 강의가 낸 과제는 "같은 계획표로 자기 에이전트에게 시켜 만들고 공유하라"이고, 재현할 능력은 코딩이 아니라 **지시**다("어차피 코딩 우리가 안 한다"). `#3`
- [ ] **구현에는 입력이 둘: 계획표(무엇을, 이 제품 한정) + 스킬셋(어떻게, 다음 프로젝트까지).** 계획표만 들고 시작하면 산출물 모양이 매번 달라져 사람이 매번 코드를 처음 읽게 된다. `#3`
- [ ] **조직 트리는 독립 기능이 아니라 `인가권한 중간 관리자 위임`의 구현체다.** 위임에는 범위를 표현할 단위가 필요하다. `#3`

## 불변 트레이드오프 — 모르면 잘못된 선택을 반복한다

- [ ] **자율성 ↔ 결정성:** 모델에 제어권을 넘길수록(에이전트化) 창의적이지만 예측 불가·뽑기·토큰 폭탄이 심해진다.
- [ ] **전용 도구 ↔ 범용(쉘) 도구:** 전용 도구는 약한 모델의 실수를 줄인다. 범용 쉘 하나로 비비려면 강한 모델이 필요하다. (Claude Code=전용 다수, Codex=쉘 통합)
- [ ] **프로세스 실행 ↔ 인메모리 실행:** 프로세스는 본체가 안전(도구가 죽어도 에이전트는 멀쩡)하나 직렬화·통신 비용. 인메모리는 빠르나 블로킹 시 에이전트 전체가 늘어짐(특히 단일 이벤트 루프).
- [ ] **기능을 코드에 가두면 = 워크플로우, 도구로 주면 = 모델 제어.** 도구 설계 = 제어권 배분.
- [ ] **컨텍스트 크기 ↔ 비용:** 컨텍스트가 클수록 KV 캐시가 VRAM을 더 잡아먹는다. 컨텍스트 축소는 성능이 아니라 비용 정책이다.
- [ ] **세션별 인스턴스 ↔ 스트림 서버:** 인스턴스(클로드 코드)는 클라이언트가 세션을 점유해 단순하지만 다중 클라이언트가 안 된다. 스트림(코덱스)은 점유를 없애 모바일·브라우저·CLI가 같은 세션을 동시에 보게 하지만 이벤트 큐 인프라가 필요하다. `#2`
- [ ] **압축률 ↔ 열화:** 모델 요약은 턴 로그 95%를 5%로 줄인다(전체 10% 잔존) → 정보 대량 분실 + 요약 자체의 할루시네이션 위험. 그리고 **어떤 압축 방식을 골라도 결국 슬라이딩 윈도우가 붙는다** — 압축률만으로 무한 증가를 못 막는다. `#2`
- [ ] **도커 ↔ 네이티브 설치:** 도커는 컨테이너 격리로 보안이 거의 완벽하나 개별 OS 네이티브 개발이 막히고, **RHEL 엔터프라이즈 + 사내 보안은 컨테이너를 차단**한다. 네이티브는 다 되지만 보안 심사가 까다롭다. `#2`
- [ ] **마스터 권한을 DB에 두기 ↔ 환경변수에 두기:** DB면 운영 중 바꿀 수 있으나 **DB 쓰기 권한자가 스스로 마스터가 된다.** 환경변수면 그 승격 경로가 막히는 대신 **재기동**이 필요하다. `#3`
- [ ] **단위 테스트 ↔ 인수 테스트 (에이전트가 코드를 쓸 때):** 단위 테스트의 "실패 위치 좁히기" 값이 떨어진다 — 좁혀 줘도 에이전트는 다시 뽑을 뿐이다. **단 전제는 CRUD·화면처럼 순수 로직이 얇은 영역**이고, 판정 기준이 명확한 로직에는 단위 테스트가 **명세 그 자체**로 남는다. `#3`

## 의사결정 경계 — 설계·운영 순간에 즉시 필요

- [ ] **4시-7시 규칙:** 컨텍스트 도넛을 시계로 볼 때 **4시**에 마지막 요청을 날려라(성능 최고점). 7시가 마지노선, **9시 이후·컴팩션 후는 다 쓰레기**. (민감/어려운 작업 기준의 경험칙)
- [ ] **폴더 격리 = 바이브 코딩의 최강 가드레일.** 단 하나의 파일이어도 폴더로 격리하라 → 뽑기(비결정성)가 그 폴더 안에서만 일어난다. 격리 없이는 제품 지속 개발 불가.
- [ ] **로컬 LLM 모델 하한: 약 200B 이상.** 30B·120B는 제품 수준 코딩 불가. MiniMax M2급(~200~220B)이 진입점.
- [ ] **로컬 LLM 양자화 하한: Q5 이상.** Q4는 아무리 커도 소용없다(원본 분포에서 벗어나 사실상 다른 모델). KL 발산 ~0.03 이내에 들려면 Q5.
- [ ] **기반 컨텍스트 예산 = 모델 컨텍스트의 5% 이내** (코덱스 실측 약 4%). 넘으면 주인공(실제 작업)이 자리를 잃는다. `#2`
- [ ] **컴팩트 트리거 = 컨텍스트 80% 지점.** 단 80%는 메모리가 아니라 **보낼 메시지를 파싱한 토큰 수** 기준이다. `#2`
- [ ] **유휴 세션 KV 캐시는 약 20분 뒤 내려간다** → 재입장 지연을 막으려면 디스크 직렬화(영속화)와 복원이 필요하다. 포크는 캐시 복사라 즉시 된다. `#2`
- [ ] **AGENTS.md/CLAUDE.md는 작업 위치 기준 계층 병합 후 200K로 축소된다.** 단순 연결이 아니다. `#2`
- [ ] **CLI형 클라이언트는 세션 하나만 감당한다.** 다중 세션은 창을 여러 개 띄워야 한다(tmux). 금융권 등 터미널 전용 환경의 제약. `#2`
- [ ] **착수 순서의 기준은 뒤집기 비용의 역순.** 매우 비싼 다섯: **계정 영구 키 / 세션 토큰 성질 / 조직 루트 개수 / 모노레포 경계(프로토콜 위치) / i18n 도입 시점.** `#3`
- [ ] **구현 판정은 다섯이다: 구현 / 부분 / 축소 / 변경 / 미구현.** 구현·미구현만으로 보면 접힌 것을 접힌 줄 모르고 지나간다. `#3`
- [ ] **모델 할당의 두 축: 개인별=예산(토큰 소진 시 무중단 전환) / 조직별=접근 권한.** 3강은 권한 축만 만들고 예산 축을 접었다 — 접힌 쪽이 2강이 "핵심 요구"라 부른 것이다. `#3`
- [ ] **세션 유휴 만료와 기록 보관 기간은 목적이 반대라 별개 설정이다** (보안 ↔ 감사·디스크). `#3`

## 구현 규칙 — 만들 때 어기면 나중에 전면 재작업 `#2`

- [ ] **기반 컨텍스트는 세션 도중 바꾸지 않는다** — 앞부분이 불변이어야 프리픽스 캐시가 산다. 그래서 **세션 중 모델 교체 = 기반 컨텍스트 변경 = 재로딩**이고, 그 때문에 경고가 뜬다.
- [ ] **도구·스킬 리스트는 상수가 아니라 계산 결과다.** 스킬별 도구 한정 × 에이전트별 도구 지정 × 퍼미션(인가)이 겹쳐 정해진다.
- [ ] **이름 충돌 우선순위 규칙은 필수 아키텍처 요소다.** 스킬뿐 아니라 MCP·툴·프롬프트·커맨드·플러그인·룰스 전부에서 같은 충돌이 발생한다.
- [ ] **컴팩션 판정 지점을 턴 시작 한 곳에만 두면 안 된다** — 도구 호출이 몰리고 리즈닝이 길어지면 한 턴 안에서 컨텍스트가 소진된다. 잘림 정책(롤링 윈도우/중간 절단/정지) 3종은 모두 코딩에 치명적이므로 그 전에 컴팩트해야 한다.
- [ ] **정책 서버(비즈니스 서버)를 에이전트보다 먼저 만든다.** 권한·모델 할당·저장 위치·가드레일은 에이전트가 참조해야 하는 입력이다. 순서를 뒤집으면 에이전트 코어를 재작업한다.
- [ ] **모노레포 참조는 `apps` → `packages` 단방향.** `packages`(핵심 도메인)에는 react·express 지식과 무관한 순수 도메인 로직과 모델만 들어간다.
- [ ] **도메인 패키지는 `common`·`server`·`front`.** 기준은 "양쪽이 같은 규격을 봐야 하는가" — **프로토콜 타입은 `common`**. 양쪽에 따로 선언하면 어긋남을 컴파일러가 못 잡는다. `#3`
- [ ] **퍼미션은 미들웨어 한 층, 기본값은 거부.** 엔드포인트마다 붙이면 빠뜨린 곳이 **조용히 열린다.** `#3`
- [ ] **규칙에는 검사 스크립트를 짝으로 붙인다** — 문서의 규칙은 지시이고 **검사만이 판정**이다. `#3`
- [ ] **스킬 문장은 위반의 지위를 못박는다: `violation, not a to-do` / `failures, not warnings` / "확인하지 않은 것은 성공이 아니다".** 목표는 **`impossible rather than merely discouraged`**. `#3`
- [ ] **스킬 본문은 이 레포에서만 참인 것만 담는다** (`Skip generic coding knowledge`). 일반론은 기반 컨텍스트 예산만 먹는다. `#3`
- [ ] **에이전트 출력 형식을 `key=value`로 고정하고 최종 답변을 그 블록에 근거하도록 묶는다** — 보고와 실제가 어긋날 수 없게. `#3`
- [ ] **i18n은 처음부터. 플랫 키(grep 가능) + 전 언어 동일 키셋 + 뷰에 리터럴 금지.** RTL 로케일(`ar`)은 **load-bearing** — 빼면 레이아웃이 한 방향으로 굳고 부채가 복리로 쌓인다. `#3`
- [ ] **한 세션 = 한 작업 단위(화면의 한 부분).** 세션 크기가 뽑기의 영향 범위와 되돌리기 단위를 정한다. `#3`
- [ ] **관리자 권한 범위 2종(노드 단독 / 하위 계층 전체)이 있어야 위임이 산다.** 하위 전체가 **나중에 생기는 노드**까지 포함한다. 위임은 재귀적이되 **자기 권한을 넘지 못한다.** `#3`

## 비즈니스 제품 요구 — 납품 판단 `#2`

- [ ] **직접 만드는 유일한 사업적 근거 = 온프레미스.** 온프레미스가 깨뜨리는 것 셋: **웹 검색 / 외부 모델 / 보안 프로그램과의 공존.**
- [ ] **에이전트 코어는 차별화 지점이 아니다** — 기업도 "그게 그거"로 본다. 팔리는 이유는 **조직 관리 · 사내 정보시스템 · 일반 업무 겸용 · 모델 라우터 · 전사 가드레일**이다.
- [ ] **모델 라우터의 핵심 요구 = 엔터프라이즈 할당 토큰 소진 시 사내 LLM 무중단 전환.** 최소 기능은 "개인이 쓸 모델을 서버가 내려주기".
- [ ] **온프레미스 라이센스 = 타임 서버 없음 = 컴퓨터 시간을 믿어야 함** → 시간 조작 방어가 필수. 웹 검색은 벡터DB 인덱스로 대체하고 "언제까지의 인덱스"로 스냅샷 판매·갱신 과금한다.
- [ ] **고객군 = 금융권·증권사·제조사·공장 (산업용).** 유통은 파트너 경유.
- [ ] **회사 이메일은 고유하지 않다** — 퇴사자 주소를 신입이 받는다. 영구 키로 쓰면 두 사람의 이력이 섞여 **감사의 "누가"가 무너진다.** `#3`
- [ ] **세션 헤더·쿠키 이름은 설정으로 뺀다** — 사내 L7 방화벽이 헤더를 감시하므로 **이름이 보안팀 협의 대상**이다. **쿠키 자동 전송은 브라우저뿐**이라 앱용 헤더 경로가 함께 필요하다. `#3`
- [ ] **조직 루트는 여러 개일 수 있다.** 하나로 제한하는 것이 가장 흔한 실수이고, **허용은 공짜인데 제한은 전면 수정**이라 비대칭이 기본값을 정한다. `#3`

- [ ] **현재 Claude 컨텍스트 창:** Opus 4.8 / Opus 4.7 / Sonnet 5 / Fable 5 = **1M**, Haiku 4.5 = **200K**.

## 진단 신호 — 증상을 원인에 즉시 매핑

- [ ] **모델이 자꾸 사과한다("제가 틀렸습니다")** → 컨텍스트 희석. 원인은 모델이 아니라 **내가 흘린 모순된 지시들**의 누적(어텐션 문제 아님).
- [ ] **단계별 작업 중 모델이 점프하거나 도중에 끝낸다** → 로그가 길어져 초반 지시를 까먹음. **리마인더** 훅으로 현재 단계를 근처에 재삽입.
- [ ] **약한 모델이 같은 말만 반복(리즈닝 루프)** → 스트림 가드 훅으로 중간에 끊어라.
- [ ] **로컬 모델이 "성능이 안 난다"** → 대개 Q5 이하(Q4·Q3)를 쓴 것. 또는 200B 미만.
- [ ] **바이브 코딩 제품이 수정 쌓일수록 자꾸 깨진다** → 폴더/모듈 격리 실패로 뽑기가 전역에 퍼짐.
- [ ] **도커로 만들었는데 고객사 엔터프라이즈 환경에서 안 뜬다** → RHEL 엔터프라이즈 + 사내 보안이 컨테이너를 차단한 것. 네이티브 설치형이 필요하다. `#2`
- [ ] **윈도우에서 파워셸 명령이 계속 깨진다** → 파워셸 기본 인코딩이 OS 언어를 따라 **CP949**가 된 것. 파워셸 7.0으로 올리면 UTF-8 지정 가능. (또는 WSL 실행으로 전환 — 모델이 리눅스 환경으로 트레이닝됨) `#2`
- [ ] **서버가 죽는 원인 1위는 로그 적재.** 세션·감사 기록 보관 기간을 **처음부터** 설정으로 뺀다. `#3`
- [ ] **컨테이너에서 호스트 서비스로 연결이 안 된다** → `localhost`를 쓴 것. **Docker 안의 `localhost`는 컨테이너 자신**이고, **개발 중엔 통했기 때문에 배포 후에만 깨진다.** `#3`
