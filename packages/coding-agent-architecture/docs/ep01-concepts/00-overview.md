# 00. 개요 — 코딩 에이전트를 "만드는 사람"의 관점

## 학습 목표

이 자료를 다 읽으면 (1) 바이브 코딩 에이전트(Claude Code·Codex 같은)가 내부적으로 **어떤 구성 요소**로 이루어지는지 설명할 수 있고, (2) 그 구성 요소를 직접 구현할 때 **어떤 설계 판단**을 내려야 하는지 근거를 들어 말할 수 있으며, (3) 실무에서 에이전트를 **잘 쓰기 위한** 규칙(컨텍스트 관리, 폴더 격리, 4시-7시 규칙)을 원리와 함께 적용할 수 있다.

## 이 자료의 성격

이 자료는 뉴런데브 채널의 라이브 강의 "코딩에이전트 만들기 #1"의 내용을 학습용으로 재구성한 것이다. 강의의 핵심 전제는 이것이다:

> **에이전트를 잘 쓰는 것(운전)과 에이전트를 만드는 것(자동차 제조)은 완전히 다른 능력이다.**

우리는 매일 바이브 코딩을 하니까 에이전트를 잘 안다고 착각하기 쉽지만, 막상 만들려고 하면 "에이전트란 무엇인가", "세션이란 무엇인가", "도구란 무엇인가"를 **구현 가능한 개념**으로 분해해야 한다. 마케팅 용어("멀티 에이전트 팀", "에이전트끼리 통신")나 은유법에 기대면 코드를 짤 수 없다. 이 자료는 그 은유들을 **세션·턴·도구·훅**이라는 구현 가능한 실체로 환원하는 것이 목표다.

강의는 온프레미스 로컬 LLM 환경에서 동작하는 회사 전용 코딩 에이전트를 납품하는 실무 수요에서 출발한다. 그래서 "모델이 약할 때 에이전트가 어떻게 보완해야 하는가"라는 관점이 자료 전반에 깔려 있다 — 이것이 클로드/오픈AI처럼 강력한 모델을 전제로 한 일반 문서와 다른 점이다.

## 큰 그림 — 에이전트 = 모델의 제어권 확장

이 자료를 관통하는 단 하나의 원리가 있다:

> **에이전트의 모든 구조물(세션·서브에이전트·골·도구·훅)은 결국 "모델에게 얼마나 많은 제어권을 넘길 것인가"의 문제로 수렴한다.**

- 초기 에이전트: 모델은 **도구 호출로 루프를 끝낼지 말지**만 제어했다.
- 현대 에이전트: 모델이 **새 턴을 만들지(골), 서브에이전트를 열지, 다른 세션과 메시지를 주고받을지, 모델을 바꿀지, 컴팩션을 할지, 스케줄러를 걸지**까지 제어한다.
- 그 제어권을 넘기는 유일한 통로가 **도구(tool)**다. 어떤 기능을 코드에 가두면 사람이 만든 워크플로우가 되고, 같은 기능을 도구로 주면 모델이 자율적으로 제어하는 에이전트가 된다.

이 하나의 렌즈로 나머지 모든 챕터를 읽으면 개별 개념이 흩어지지 않고 하나로 연결된다.

- 바이브 코딩 도구(Claude Code / Codex / Cursor 등)를 **사용자 입장에서** 써 본 경험
