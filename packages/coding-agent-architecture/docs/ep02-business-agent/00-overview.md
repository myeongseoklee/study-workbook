# 00. 개요 — 기업형 바이브코딩 에이전트 (코딩에이전트 만들기 #2)

## 이 회차가 답하는 질문

강의 #1이 "에이전트란 무엇인가"였다면, #2는 **"그걸 실제로 만들어 기업에 납품하려면 무엇을 알아야 하는가"**다. 두 축으로 갈린다.

1. **세션과 컨텍스트의 실체** (1~4장) — 도구 호출 루프만 붙여서는 바이브 코딩이 되지 않는 이유. 세션·컨텍스트 조립·컴팩션이 각각 어떤 난제인지.
2. **비즈니스 제품으로서의 요구** (5~10장) — 왜 온프레미스가 시장을 만드는지, 기업이 실제로 요구하는 것이 무엇인지, 어떤 순서로 만들지.

강의의 출발 진단은 이것이다.

> **"시중에 나와 있는 에이전트 책들을 보고 도구 사용 좀 붙이면 바이브 코딩이 될 것 같지만, 안 된다."**

## 이 회차의 뼈대 개념 셋

세부를 잊어도 이 세 문장은 남아야 한다.

1. **세션 = KV 캐시 식별 ID.** 그래서 세션 수가 곧 메모리 비용이고, 프리픽스 캐시를 살리려면 컨텍스트 앞부분이 불변이어야 한다.
2. **컨텍스트가 append-only 불변 리스트라서** 세션 서버가 이벤트 소싱(스트림) 구조로 수렴한다. 그리고 그 불변성이 컴팩션을 어렵게 만든다.
3. **에이전트 코어는 차별화 지점이 아니다.** 팔리는 이유는 온프레미스 대응·조직 관리·가드레일·모델 라우팅이다.
