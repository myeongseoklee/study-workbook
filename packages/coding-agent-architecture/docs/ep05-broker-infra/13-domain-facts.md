# 13. 도메인 사실 목록 (5강)

앞의 장들이 "왜"를 다뤘다. 이 장은 **슬라이드·화면·발화로 확인된 사실만** 모은다. 자기 구현이나 견적을 낼 때 참조하는 목록이고, 추론과 보충 설명은 넣지 않았다 — 확인되지 않은 것은 명시적으로 표시한다.

> **전사 품질 주의.** 이 회차는 자막 없는 라이브 아카이브라 로컬 STT로 전사했다. 자동 전사는 고유명사를 자주 틀린다(`PGMQ` → `PG&Q`·`피지큐`, `Qwen` → `QN`·`Q1`). **아래에서 화면으로 교차 확인된 항목만 확정으로 적었고, 발화만 있는 것은 그렇게 표시했다.**

## 아키텍처 참가자 (슬라이드 「참가자 구성」 `[10:00]` 전문)

| 참가자 | 슬라이드가 적은 것 |
|---|---|
| **PGMQ** | 간단한 메시지큐 서버로 `write` · `read` · `delete` · `set_vt` · `archive` **5가지 연산만 지원** / 꺼내기와 지우기가 분리되어 있어 그 사이에 죽으면 메시지가 살아남(신뢰성) / **PG 테이블과 통합되어 하나의 트랜잭션으로도 처리 가능** |
| **이벤트 브로커** | 클라이언트가 실제로 접속하는 서버 / PGMQ에서 클라이언트가 수신을 원하는 채널용 이벤트만 모아서 송신 / 클라이언트는 요청을 이벤트로 만들어 브로커에게 전달하면 브로커가 PGMQ에 삽입 / **오직 이벤트 전송만 담당하고 아무런 처리도 하지 않음** / 여러 개의 이벤트 브로커를 운영하여 다수 클라이언트 접속도 PGMQ가 감당하는 이상 확장 가능 |
| **클라이언트** | 이벤트 브로커에 소켓으로 연결됨 / 원하는 이벤트 카테고리(채널)만 수신하고 필요한 요청을 이벤트로 만들어 브로커에 전송 / 양방향 통신이 기본이라 소켓으로 처리 |
| **워커 서버** | PGMQ에 접속하여 자신이 처리해야 하는 이벤트를 가져간 뒤 처리 후 다시 이벤트 등록 / 처리하는 이벤트 종류에 따라 워커 서버도 여러 대 운영 가능 |

## MQ 신뢰 보정 (슬라이드 「MQ신뢰보증」 `[26:30]`)

| 시점 | 무엇 |
|---|---|
| `read` | 워커가 메시지를 꺼냄 |
| `set_vt` | visibility timeout 시작 — **다른 워커에게 숨김** |
| 처리 중 (숨겨진 구간) | 이 구간에 워커가 죽으면? → `delete`가 호출되지 않음 → timeout 지나면 메시지 다시 보임 → **다른 워커가 대신 처리** |
| `delete` | 처리 완료 후 삭제 → 메시지가 큐에서 영구 제거 → **딱 한 번만 처리됨** |

- `set_vt`는 **원자성 연산** — 두 워커가 같은 메시지를 동시에 집을 수 없다 `[26:30]`

## 큐로 읽기와 로그로 읽기 (슬라이드 `[28:20]` 전문)

전제 문장: **"큐는 정확히 한 명에게 주려고 만들어졌고, 로그는 여럿이 보라고 만들어졌다. 결과 경로에 필요한 것은 후자였다."**

| | 큐 · 경쟁 소비 | 로그 · 팬아웃 tail |
|---|---|---|
| 대상 테이블 | `agent_results` 하나를 브로커 셋이 함께 읽는다 | `event_store`를 브로커 셋이 각자 자기 위치부터 따라 읽는다 |
| 성질 | **"읽기가 쓰기다"** — `read` = `UPDATE`(visibility timeout 설정), `delete` = `DELETE` | **"읽는 건 읽기다"** — `SELECT … WHERE position > $cursor ORDER BY position LIMIT n` |
| 부작용 | 브로커를 N대로 늘리면 **write도 N배**. 같은 행을 두고 경합까지 붙는다 | 모두 같은 꼬리를 읽는다. 그 페이지는 이미 **shared buffer**에 있다 |
| 관측 예 | 브로커 A가 먼저 `read` → B는 자기 것(ch: B)을 못 본다 | append only · 한 번 적히면 수정되지 않는다. 브로커별 cursor 103 / 104 / 105 |
| 봉합 비용 | **라우터 프로세스 · 브로커별 전용 큐 · 두 번째 outbox · identity lease · 전용 테이블 3개** → *"봉합의 값이 원래 문제보다 크다"* | **"봉합할 것이 없다"** — 위 다섯이 한꺼번에 근거를 잃는다 |
| 브로커의 상태 | 위 장치들의 상태 | **커서 하나와 소켓 맵뿐 — 내구 저장이 없다** |
