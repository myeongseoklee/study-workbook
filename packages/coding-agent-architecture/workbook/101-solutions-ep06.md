# 워크북 해설 (6강)

1. 이벤트 하나를 처리하고 워커가 반환하면 오래 살아 있는 스레드와 세션 결합이 줄어든다. 모델 추론은 긴 작업이라 별도 생존 주기가 필요하다.
2. 캐시가 성립하면 처리 비율이 짧은 구간에 급격히 100%에 가까워진다. 깨지면 전체 컨텍스트를 다시 계산하므로 천천히 오른다.
3. 프리필은 긴 프롬프트의 KV를 한꺼번에 준비해 무겁고, 디코드는 토큰 하나씩 처리해 상대적으로 가볍다. 긴 컨텍스트의 핵심 비용은 VRAM에서 읽을 양이다.
4. AI가 생성 속도를 올려도 구조 부채도 함께 빨리 쌓인다. 따라서 새 기능보다 구조를 읽고 이름·경계·중복을 계속 정리하는 데 더 많은 시간을 배분한다.
5. 프리픽스 캐시 불성립 또는 매 요청 전체 재계산을 의심한다. 실제 컨텍스트 크기, 캐시 hit 여부, processing 비율의 상승 모양을 함께 확인한다.
6. 같은 개념을 여러 이름으로 부르면 경계와 책임이 합의되지 않았다는 뜻이다. 코드를 더 생성하기 전에 용어 하나와 책임 하나를 확정해야 한다.
7. 나중의 리팩토링은 이미 붙은 호출자·데이터·이벤트 계약을 함께 뒤집는다. 기능을 만들 때부터 각 단계가 독립적으로 안전한지 확인해야 되돌리기 비용을 제한할 수 있다.
8. 세션별로 `Map<sessionId, Map<sequence, Event>>`에 넣고, 세션의 첫 등장 순서를 별도로 기억한 뒤 시퀀스로 정렬한다.
9. `[68, 91, 100]`은 캐시가 재사용되어 짧은 재계산 뒤 완료되는 모양이다. `[12, 34, 56]`은 캐시가 깨져 매번 전체를 처리하는 의심 신호다.
