# 워크북 (3강) — 계획을 구현으로 내리고, 에이전트에게 시키기

## 이 워크북이 1·2강 것과 다른 이유

[92-workbook.md](92-workbook.md)는 **회수 연습**이다 — 자료를 덮고 정의·수치를 꺼내는 훈련. 3강은 성격이 다르다. 강의가 낸 과제가 "이해하라"가 아니라 **"같은 계획표로 네 에이전트에게 시켜서 만들고 스크린샷 공유하라"**이기 때문이다.

그래서 문항 형태를 바꿨다.

| 파트 | 형태 | 무엇을 훈련하나 |
|---|---|---|
| 1 | **대조표 복원** | 계획 한 줄이 구현에서 어떻게 갈리는지, 무엇이 접혔는지 |
| 2 | **스킬 문장 고쳐쓰기** | 애매한 지시를 어기지 못하는 문장으로 바꾸는 능력 |
| 3 | 코딩 과제 3개 | 판정 가능한 조각 |
| 4 | **자기 구현** | 강의가 실제로 낸 과제 |
| 5 | 오답 노트 | — |

정답은 [95-solutions-ep03.md](95-solutions-ep03.md)에 있다. 파트 2는 정답이 하나가 아니지만, **강의자의 실제 스킬 문장**이 기준으로 제시된다.

코딩 과제 풀이는 별도 브랜치에서 한다 (레포 [`README.md`](../../../README.md) § 규약 4).

## 파트 1. 대조표 복원

> 정답: [95-solutions-ep03.md](95-solutions-ep03.md) 파트 1

자료를 덮고, 2강 계획표의 각 줄이 3강에서 어떻게 됐는지 채운다. 판정은 **구현 / 부분 / 축소 / 변경 / 미구현** 다섯 중 하나다.

**1-1.** 계획표 4개 항목의 제목과 각 항목의 판정(2강이 스스로 붙인 것)을 쓰라.

**1-2.** `1. 인증인가`의 하위 항목 **세 개**를 쓰고, 각각이 3강에서 어떻게 구현됐는지와 판정을 채우라.

| 하위 항목 | 3강 실제 | 판정 |
|---|---|---|
|  |  |  |
|  |  |  |
|  |  |  |

**1-3.** 위 셋 중 **부분**으로 남은 것은 무엇이고, 정확히 무엇이 빠졌는가? 자기 구현에서 그 자리를 열어 두려면 무엇을 해야 하는가?

**1-4.** 3강에서 만든 **조직 트리**는 계획표의 어느 줄에 대응하는가? 이것을 독립 기능으로 이해하면 무엇을 잃는가?

**1-5.** `3. 모델라우터`의 계획과 구현 사이에 **축의 변경**이 있다. 무엇이 무엇으로 바뀌었는지 쓰고, 두 축이 각각 어떤 문제를 해결하는지 대조하라.

**1-6.** 그 변경으로 **접힌 것**은 무엇인가? 그것이 2강에서 어떻게 불렸는지도 쓰라.

**1-7.** 계획표에 **없었는데** 3강 산출물에 들어온 것을 넷 이상 대고, 그것들의 출처를 한 단어로 말하라.

**1-8.** 착수 순서를 정하는 기준을 쓰고, 그 기준으로 **가장 먼저 확정해야 할 결정 다섯**을 대라.

**1-9.** 아래 결정들의 뒤집기 비용을 **높음/낮음**으로 가르고, 높은 쪽에 대해 "무엇이 함께 움직이는가"를 한 줄로 쓰라.

- 마스터 계정을 DB에 둘까 환경변수에 둘까
- 계정의 영구 키를 이메일로 할까 사번으로 할까
- 세션 유휴 시간을 7200초로 할까 3600초로 할까
- 조직 루트를 하나로 할까 여럿으로 할까
- 모델 등록 단위를 모델로 할까 프리셋으로 할까

**1-10.** 미룬 항목에 무엇을 함께 적어야 하는가? `공유드라이브 설정기능`을 예로 들어 구체적으로 쓰라.

## 파트 2. 스킬 문장 고쳐쓰기

> 기준 답안: [95-solutions-ep03.md](95-solutions-ep03.md) 파트 2

아래는 **애매해서 지켜지지 않을 지시**들이다. 각각을 에이전트가 어기지 못하는 문장으로 고쳐 쓴다. 05장의 기법을 쓰되, 무엇보다 **위반의 지위**와 **실패 양상**이 문장에 들어가야 한다.

**2-1.** `번역 파일의 키는 가능하면 모든 언어에 다 넣어 주세요.`

**2-2.** `배포 후에는 서비스가 잘 뜨는지 확인해 주세요.`

**2-3.** `함수를 너무 잘게 쪼개지 마세요. 적당히 나누면 좋습니다.`

**2-4.** `i18n 리소스는 되도록 중첩하지 말고 평평하게 써 주세요.`

**2-5.** `배포 결과를 보고해 주세요.`
→ 이 문항은 **출력 형식까지** 지정해야 한다. 그리고 모델이 형식만 흉내내고 내용을 지어내는 것을 막는 한 문장을 덧붙이라.

**2-6.** 아래 스킬 문장에서 **`ar`(아랍어)이 목록에 있는 이유**를 유지하면서, 왜 그 이유를 반드시 적어야 하는지 한 문단으로 설명하라.

```
Required languages — at minimum these eight:
en / ko / zh / es / hi / ar / fr / pt
```

**2-7.** 스킬 본문 첫 줄에 `Apply repo-only constraints. Skip generic coding knowledge.`를 적는 이유를 쓰라. 이것을 빼면 무엇이 나빠지는가?

**2-8.** 아래는 새 프로젝트용 스킬의 `description` 초안이다. 무엇이 빠졌는지 지적하고 고쳐 쓰라.

```
description: 우리 회사 웹 프로젝트의 코딩 규칙을 담은 스킬입니다.
```

## 파트 3. 코딩 과제

> 코딩 과제는 **실행 가능한 파일**로 준비돼 있다. `tests/`가 무엇을 만들지 정의하니 **먼저 읽고**, `src/`의 `🎯 TODO`를 채운 뒤 `pnpm test {번호}`로 판정한다. `solutions/`는 통과한 뒤에 여는 것이다.

```bash
git switch -c sol/coding-agent-architecture/e03-02-01
cd packages/coding-agent-architecture
pnpm test e03-02-01
```

**3-1. 세션 생명주기** — `src/e03-02-01-session-lifecycle/index.ts`

계획표 `1-a`(중앙에서 세션키 모니터링 및 변경가능)의 판정 가능한 조각이다. 유휴 만료·강제 제거·보관 기간 정리를 구분해 구현한다. 만료와 삭제를 한 사건으로 합치면 감사 기록이 사라지고, 만료 확인 없이 갱신하면 죽은 세션이 되살아난다.

- 소요 예상: 30~40분
- 막히면: [`../docs/ep03-admin-implementation/02-identity-and-session.md`](../docs/ep03-admin-implementation/02-identity-and-session.md)

**3-2. 조직 트리와 권한 범위** — `src/e03-03-01-org-tree/index.ts`

계획표 `1-c`(인가권한 중간 관리자 위임)의 조각이다. 다중 루트, 순환 방어, 권한 범위 2종, 가장 가까운 조상의 모델 할당을 구현한다.

- 소요 예상: 50~70분
- 막히면: [`../docs/ep03-admin-implementation/03-delegation-and-org.md`](../docs/ep03-admin-implementation/03-delegation-and-org.md)

**3-3. i18n 키셋 감사** — `src/e03-06-01-i18n-keyset-audit/index.ts`

**스킬이 요구하는 검사 스크립트를 직접 만드는 과제다.** 규칙을 적어 두는 것은 지시이고 검사가 판정이라는 차이를 손으로 확인한다. 키셋 비교의 **기준을 무엇으로 잡는가**가 핵심이다.

- 소요 예상: 30~40분
- 막히면: [`../docs/ep03-admin-implementation/06-skill-enforced-structure.md`](../docs/ep03-admin-implementation/06-skill-enforced-structure.md)

## 파트 4. 자기 구현 (강의가 낸 과제)

> **여러분들도 이 구현계획표를 보고 여러분들 에이전트한테 시켜 가지고 만들고 스크린샷 공유하고** 뭐 이런 식으로 진행할 거거든요. — 2강 [1:20:00]

| 모노레포 경계 |  |  |  |

**4-2. 스킬을 먼저 세운다**

구현 전에 최소 두 개의 스킬 문서를 쓴다.

- 하나는 **경계**를 강제하는 것 (폴더 배치 / 참조 방향 / 프로토콜 위치)
- 하나는 **검증**을 강제하는 것 (무엇이 성공이고, 어떤 형식으로 보고하는가)

각 스킬에 파트 2에서 연습한 문장 형태를 쓴다. 그리고 **검사 스크립트를 하나라도** 붙인다.

**4-3. 세션을 쪼개 시킨다**

작업을 세션 단위로 나눈 목록을 만든다. 입자 크기의 기준은 **화면의 한 부분**이다. 목록이 곧 되돌리기 단위가 된다.

**4-4. 검증하고 남긴다**

내장 브라우저 스크린샷 또는 동등한 수단으로 확인하고, 결과를 **날짜별 리포트**로 남긴다. 세션 로그로 대체하지 않는다.

**성공 기준** — 동작 여부가 아니다. 판정 체크리스트가 95에 있다.
