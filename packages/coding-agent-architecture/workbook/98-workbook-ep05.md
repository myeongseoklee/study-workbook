# 워크북 (5강) — 무엇을 모르기로 했는지 되짚기

## 이 워크북의 형태

회차마다 형태가 달랐다. [92](92-workbook.md)는 회수 연습, [94](94-workbook-ep03.md)는 계획→구현 판단, [96](96-workbook-ep04.md)는 결정 하나가 만드는 연쇄 추적이었다. 5강은 **각 계층이 무엇을 모르기로 했는지**가 내용이고, 후반부는 성격이 아예 다른 **구매 판단 산수**다. 그래서 문항도 그렇게 갈랐다.

| 파트 | 형태 | 무엇을 훈련하나 |
|---|---|---|
| 1 | **무지 추적** | 각 계층이 모르는 것과 그 대가로 얻는 것. 하나를 알게 하면 무엇이 무너지는가 |
| 2 | **경로 판별** | 작업 경로와 결과 경로. 어느 쪽으로 읽어야 하는지 시나리오로 가르기 |
| 3 | **견적 산수** | 로컬 모델·하드웨어를 숫자로 판단하기 |
| 4 | 코딩 과제 4개 | 판정 가능한 조각 |
| 5 | **자기 설계** | 자기 시스템의 결정 목록 채우기 |
| 6 | 오답 노트 | — |

정답은 [99-solutions-ep05.md](99-solutions-ep05.md)에 있다. 코딩 과제 풀이는 별도 브랜치에서 한다 (레포 [`README.md`](../../../README.md) § 규약 4).

> **파트 1은 `90-must-memorize.md`의 `#5` 카드 41장과 1:1이 아니라 묶음 대응이다.** 한 문항이 카드 여러 장을
> 함께 검증한다 — 예를 들어 1-1 하나가 참가자 넷의 카드를 한꺼번에 묻는다. 회차 형태를 "무지 추적"으로
> 잡았기 때문이고, 1:1로 쪼개면 같은 것을 네 번 묻는 문항이 생긴다. **카드 쪽을 기준으로 빠진 것을 확인하고
> 싶으면 `90`을 직접 훑는 편이 빠르다.**

> **파트 1·2를 자료 덮고 하라.** 이 회차는 슬라이드가 잘 정리돼 있어서 열어 두고 풀면 베껴 쓰기가 된다.
>
> **파트 3은 계산기를 써도 된다.** 외울 것은 자릿수와 판단 순서이지 산수 자체가 아니다.

## 파트 1. 무지 추적

> 정답: [99-solutions-ep05.md](99-solutions-ep05.md) 파트 1

**1-1.** 5강의 참가자 넷을 대고, 각자가 **모르는 것**과 그 무지가 허용하는 **확장 방향**을 표로 채우라.

| 참가자 | 모르는 것 | 그래서 늘릴 수 있는 것 |
|---|---|---|
| PGMQ |  |  |
| 이벤트 브로커 |  |  |
| 클라이언트 |  |  |
| 워커 서버 |  |  |

**1-2.** "이벤트 브로커는 메시지를 잘 전달해서 좋은 계층이다"라는 문장이 왜 틀렸는지 한 문장으로 쓰라. 그리고 그 문장을 뒤집어 **일반 규칙**으로 만들라 — 어떤 중간 계층을 무한 증설하고 싶을 때 무엇을 해야 하는가?

**1-3.** 브로커를 100대로 늘리면 PGMQ가 힘들어질 것 같은데 강의는 반대라고 한다. 접속 수가 어떻게 접히는지 세 층으로 그리고, **DB가 실제로 상대하는 수**가 무엇인지 쓰라.

**1-4.** 트래픽 병목 셋을 대고, 각각이 **어떤 자원을 고갈시키는지** 짝지으라. 그리고 셋 중 하나만 하드웨어로 못 고치는데 그 이유를 쓰라.

**1-5.** CPS를 택하면 **자동으로 따라오는 것 둘**이 있다. 무엇이고, 각각이 왜 선택이 아니라 귀결인지 설명하라.

**1-6.** "채널 기반 송수신은 라우팅이 효율적이라 좋다"는 설명은 무엇을 건너뛴 것인가? 진짜 목적을 쓰고, 그 목적이 달성됐을 때 **서버에 남는 상태**가 무엇인지 대라.

**1-7.** 워커가 모르는 것 셋을 대고, 각각이 만드는 성질을 하나씩 붙이라. 그리고 그중 하나가 10장(스트리밍)에서 어떤 결과를 낳는지 쓰라.

**1-8.** "기능을 껐다"와 "기능이 적체된다"의 차이를 쓰라. 진짜로 끄려면 무엇을 먼저 해야 하는가?

**1-9.** 완료 처리는 두 연산의 쌍이다. 순서를 쓰고, **뒤집으면 무엇이 남는지**와 그것이 왜 더 나쁜지 설명하라.

**1-10.** 이 구조에서 "애플리케이션을 만든다"는 것의 정의를 한 문장으로 쓰라. 그 정의가 성립하려면 **중간 계층이 무엇을 하지 않아야** 하는가?

**1-11.** "인프라는 영원히 재사용된다"는 주장이 **어디까지 참인가.** 공유해도 무관한 것과 공유하면 서로 영향을 주는 것을 각각 셋 이상 대고, 물리적 격리가 필요해질 때 쓸 수 있는 다이얼이 무엇인지 쓰라.

**1-12.** 팻 클라이언트가 이 아키텍처의 **부작용이 아니라 필연**인 이유를 서버의 무지와 연결해 설명하라. 그리고 그 두께의 비용 중 **가장 아픈 것**이 무엇이고 왜 그런지 쓰라.

**1-13.** 이 아키텍처가 대규모에 적합한데도 엔터프라이즈에서 드문 이유는 무엇인가? 그리고 **코딩 에이전트 도메인에서는 왜 그 장벽이 무료가 되는지** 쓰라.

**1-14.** 도구·스킬·전용 CLI 셋을 가르는 기준 하나를 대라. 그 기준 때문에 도구를 늘리면 무엇이 함께 늘어나는가?

**1-15.** "도구는 bash 하나만 준다"는 선택이 **어떤 전제 위에 서 있는가.** 그 전제가 깨지는 상황을 하나 들고, 그때 어느 방향으로 가야 하는지 쓰라.

**1-16.** 스트리밍이 이 아키텍처에서 "별도 기능이 아니다"라고 말할 수 있는 이유를 쓰라. 그런데 강의자는 **"공짜가 아니야"**라고도 했다. 무엇이 공짜가 아닌지 넷 이상 대라.

**1-17.** MTP·이미지 타워·오디오 타워는 서로 다른 이야기처럼 보이지만 **하나의 사실**에서 나온다. 그 사실을 한 문장으로 쓰고, 카탈로그에서 어떤 현상으로 관측되는지 대라.

**1-18.** QAT와 PTQ의 차이를 "언제 양자화하는가"로 설명하라. 그리고 **QAT의 비트 선택지가 좁은 것이 왜 결함이 아닌지** 쓰라.

**1-19.** "원본 모델이 멀티모달이니 이 튜닝본도 멀티모달이다"가 왜 성립하지 않는가? 그리고 이것이 코딩 에이전트에서 특히 치명적인 이유를 쓰라.

## 파트 2. 경로 판별

> 정답: [99-solutions-ep05.md](99-solutions-ep05.md) 파트 2

각 시나리오에서 **큐로 읽어야 하는지 로그(커서 tail)로 읽어야 하는지** 고르고 **근거**를 쓰라. 그리고 반대로 골랐을 때 처음 드러나는 증상을 함께 적으라.

**2-1.** 이벤트 브로커 세 대가 같은 결과 스트림에서 자기 구독 채널 이벤트를 골라 클라이언트에게 밀어 넣는다.

**2-2.** 워커 다섯 대가 `tool.call` 이벤트를 나눠 처리한다.

**2-3.** 감사 로그 수집기가 모든 이벤트를 통째로 데이터 웨어하우스에 적재한다. 수집기는 한 대이지만, 나중에 두 번째 수집기(실시간 알림용)를 붙일 계획이 있다.

**2-4.** 사내 대시보드가 5초마다 최근 이벤트 100건을 보여준다. 대시보드 인스턴스는 오토스케일링으로 1~8대 사이에서 변한다.

**2-5.** 아래 슬라이드가 큐 쪽에 나열한 봉합 장치 다섯을 대라. 그리고 **"봉합의 값이 원래 문제보다 크다"**는 판정을 일반화한 규칙으로 만들라 — 개별 장치는 각각 합리적으로 보이는데 왜 목록으로 모아야 드러나는가?

**2-6.** 다음 진단을 원인에 매핑하라. 각각 어느 장의 어떤 결정이 잘못된 것인가?

| 증상 | 원인 |
|---|---|
| CPU도 메모리도 여유 있는데 새 연결이 안 받아진다 |  |
| 브로커를 늘렸더니 DB 쓰기 부하가 같이 늘고 응답이 느려졌다 |  |
| 어떤 클라이언트가 자기 채널 이벤트를 못 받는다. 유실 로그는 없다 |  |
| 기능을 껐는데 큐가 계속 찬다 |  |
| 짧은 대화는 멀쩡한데 100턴 넘는 세션에서만 품질이 무너진다 |  |
| 원본은 멀티모달이라는데 스크린샷을 못 읽는다 |  |
| 추측 디코딩을 켰는데 오히려 느려졌다 |  |

**2-7.** "우리는 결과 경로도 큐로 읽는다. 지금까지 문제가 없었다"는 팀이 있다. 이 말이 참일 수 있는 조건 하나를 대고, 그 조건이 언제 깨지는지 쓰라.

## 파트 3. 견적 산수

> 정답: [99-solutions-ep05.md](99-solutions-ep05.md) 파트 3

**3-1.** 코딩 에이전트 온프레미스 견적의 **판단 순서 다섯 걸음**을 순서대로 쓰라. 그리고 그중 **가장 자주 건너뛰는 걸음**이 무엇이고 왜 늦게 드러나는지 설명하라.

**3-2.** 동시 세션 6개, 세션당 최대 컨텍스트 128K 토큰, 토큰당 KV 8KB인 워크로드다.
(a) KV 캐시가 차지하는 자리를 GB로 구하라 (1GB = 1024³).
(b) 가중치 82GB인 Q5 모델을 올린다면 총 필요량은?
(c) 128GB 장비에 들어가는가?
(d) MTP 1GB를 붙이면 어떻게 되는가?

**3-3.** 위 (c)에서 아슬아슬하다는 답이 나온다. 여기서 **KV 캐시를 Q8로 양자화해 절반으로 줄이면 되지 않나?** 이 제안의 문제를 쓰고, 문제가 **언제 드러나는지**까지 적으라.

**3-4.** 카탈로그에 다음이 있다(전부 Q5·멀티모달, MTP 없음). 워크로드는 3-2와 같다.

| 모델 | 가중치 |
|---|---|
| A | 22GB |
| B | 37GB |
| C | 82GB |
| D | 130GB |

(a) 64GB 장비에서 올릴 수 있는 가장 큰 모델은?
(b) 128GB로 올리면 몇 개가 새로 열리는가?
(c) 256GB로 올리면?
(d) 이 표가 12장의 어떤 관측을 재현하는가? 그리고 구매 판단으로 옮기면 무엇을 사야 하는가?

**3-5.** 추측 디코딩의 초안 길이를 2에서 5로 올렸더니 오히려 느려졌다. 왜 그런지 **채택 확률 p를 써서** 설명하라. 그리고 채택 임계를 0.9에서 0.75로 내렸을 때 얻는 것과 잃는 것을 각각 쓰라.

**3-6.** 후보 모델 셋을 코딩 에이전트용으로 거르려 한다. 판정 순서를 쓰고, **왜 그 순서인지** 설명하라.

| 모델 | 양자화 | 멀티모달 | 가중치 |
|---|---|---|---|
| X | Q4 | 아니오 | 500GB |
| Y | Q5 | 아니오 | 37GB |
| Z | Q5 | 예 | 90GB |

**3-7.** "메모리 128GB짜리와 64GB짜리 중 뭘 살까요"라는 질문에 **그대로 답하지 않고 되물어야 하는 것**이 무엇인가? 그리고 그렇게 되묻는 이유를 쓰라.

**4-3. 순수 라이브러리 판별식** — 과제 `e05-08-01`

- 막히면: `ep05-broker-infra/08-implementation-shape.md` · `07-infra-as-fixed-asset.md`

**4-4. 온프레미스 용량 견적기** — 과제 `e05-12-01`

12장의 판단 순서를 코드로 옮긴다. KV 캐시 누락·Q4 잔류·용량 공백 셋을 전부 잡아낸다.

- 명세: `tests/e05-12-01-vram-budget/index.test.ts` · 스켈레톤: `src/e05-12-01-vram-budget/index.ts`
- 핵심 함정: `1024³`(10⁹으로 나누면 7% 적게 나온다), 걸러내는 **순서**, 경계에서의 부동소수 비교
- 소요 예상: 30~45분
- 막히면: `ep05-broker-infra/12-capacity-planning.md`

## 파트 5. 자기 설계

> 해설: [99-solutions-ep05.md](99-solutions-ep05.md) 파트 5 — 정답이 아니라 **판정 체크리스트**다.

**5-1.** 지금 만들고 있거나 운영 중인 시스템 하나를 고르라. 5강의 다섯 질문에 답을 채우라. 답이 "해당 없음"이면 왜 그런지도 쓰라.

**5-3.** 자기 레포에서 "라이브러리"라고 부르는 패키지를 하나 고르라. `package.json`의 의존성 목록을 열고 **8장의 판별식**을 실제로 적용하라. 결과가 예상과 달랐다면 무엇 때문인지 쓰라.

**5-4.** 지금 운영 중인 시스템에서 "중간 계층에 넣고 싶은데 참고 있는 로직"이 있는가? 그것을 넣으면 무엇을 잃는지 4장의 언어로 쓰고, 그래도 넣어야 한다면 대신 무엇을 포기할지 정하라.
