# 92. 워크북 — CloudFormation으로 ECS Fargate 서비스 읽기

## 사용법

**파트 1은 자료를 덮고 푼다.** 보면서 풀면 "읽으면 아는 것"과 "꺼낼 수 있는 것"의 차이가 드러나지 않는다. 막히면 정답을 보기 전에 해당 학습 파일로 돌아가라 — 각 정답에 되짚을 위치가 붙어 있다.

정답은 [93-solutions.md](93-solutions.md)에 있다. 문항 번호가 그대로 대응한다.

**파트 1은 29문항으로 규격 상한(20)을 넘는다.** 지식 문서가 8개라 암기 카드가 29장이 되었고, 문항을 빼면 검증되지 않는 암기 항목이 생기므로 대신 **세 묶음(A·B·C)으로 나눴다.** 한 번에 한 묶음씩 풀면 된다.

**코딩 과제는 파트 3이 아니라 실행 가능한 파일로 있다.** 다섯 개이고, 각각 다른 층을 다룬다.

| 과제 | 무엇을 만드는가 | 명세 (먼저 읽는다) | 판정 |
|---|---|---|---|
| `src/1-1-cfn-dep-order.ts` | CloudFormation 의존성 순서 계산기 | `tests/1-1-cfn-dep-order.test.ts` | `pnpm test 1-1` |
| `src/2-1-sg-reachability.ts` | 보안 그룹 도달성 판정기 | `tests/2-1-sg-reachability.test.ts` | `pnpm test 2-1` |
| `src/4-1-rolling-deploy.ts` | 롤링 배포 범위·서킷 브레이커 계산기 | `tests/4-1-rolling-deploy.test.ts` | `pnpm test 4-1` |
| `src/5-1-iam-policy-eval.ts` | IAM 정책 평가기 | `tests/5-1-iam-policy-eval.test.ts` | `pnpm test 5-1` |
| `src/7-1-alarm-eval.ts` | CloudWatch 알람 상태 평가기 | `tests/7-1-alarm-eval.test.ts` | `pnpm test 7-1` |

**무엇을 만들지는 `tests/`가 정의한다.** 명세를 읽지 않고 짐작으로 코드를 쓰는 것은 학습이 아니라 추측이니 먼저 읽어라. 실패하면 메시지의 `↳ 힌트`가 어디를 의심할지 알려준다.

**`solutions/`는 통과한 뒤에 연다.** 완성된 참고 구현이 들어 있어서, 먼저 열면 그 순간 과제가 독해로 바뀐다. 통과한 다음에 읽으면 "나는 왜 다르게 했나"를 비교하는 자료가 된다.

풀이는 별도 브랜치에서 한다(레포 `README.md` § 규약 4).

# 파트 1. 회수 연습 (자료를 덮고)

> 정답: [93-solutions.md](93-solutions.md) 파트 1

### 묶음 A — CloudFormation과 네트워크 (문서 01·02)

**1-1.** 리소스에 `DeletionPolicy`를 지정하지 않고 스택을 지우면 그 리소스는 어떻게 되는가? 기본값이 다른 리소스 종류가 있는가?

**1-2.** 어떤 리소스에 고정 이름(`Name`·`GroupName`)을 주면 안 되는가? 그 이유를 교체 순서와 연결해 설명하고, 대신 무엇으로 식별하는지 답하라.

**1-3.** `DeletionPolicy: Retain`이 붙고 이름이 고정된 리소스가 있는 스택을 지웠다가 같은 템플릿으로 다시 만들면 무슨 일이 일어나는가? `UpdateReplacePolicy`를 함께 쓰지 않으면 어떤 구멍이 남는가?

**1-4.** 서브넷이 public인지 private인지는 무엇으로 결정되는가? private 서브넷 + `AssignPublicIp: DISABLED` 조합에서 반드시 있어야 하는 것과, 없을 때 실패하는 두 가지를 답하라.

**1-5.** 보안 그룹은 상태를 기억하는가? 그것이 규칙 작성에 어떤 차이를 만드는가? 그리고 새로 만든 보안 그룹의 인바운드·아웃바운드 기본값은 각각 무엇인가?

**1-6.** A에서 B로 트래픽이 가려면 어떤 규칙이 필요한가? 전용 보안 그룹에서는 이 조건 중 하나를 흔히 신경 쓰지 않게 되는데, 그것이 문제가 되는 상황은?

**1-7.** `/health`는 200을 반환하는데 비즈니스 API만 500이다. 무엇을 먼저 의심하고, 어떻게 확인하는가? 이 조합에서 배포는 성공으로 판정되는가?

**1-8.** DB 인그레스 규칙을 콘솔이나 CLI로 수동 추가하면 나중에 무엇이 막히는가? 오류 이름과 예방책을 함께 답하라.

### 묶음 B — ALB와 ECS Fargate (문서 03·04)

**1-9.** CloudFormation으로 HTTPS 리스너를 만들면서 `SslPolicy`를 생략하면 어떤 정책이 적용되고, 그것이 왜 문제인가? 콘솔에서 만들 때와 다른 이유는?

**1-10.** `HealthCheckIntervalSeconds: 30`, `UnhealthyThresholdCount: 3`, `HealthyThresholdCount: 2`일 때 장애 감지와 복귀에 각각 최대 몇 초가 걸리는가? 이 값을 줄이면 무엇을 얻고 무엇을 잃는가?

**1-11.** 타겟그룹 등록 해제 지연의 기본값은? 그대로 두면 무엇이 나빠지고, 너무 줄이면 무엇이 나빠지는가? 적정값의 기준은?

**1-12.** ALB가 503을 반환한다. 이것은 무엇을 뜻하고 원인의 범위는 어디인가? 502·504와 어떻게 구분되는가?

**1-13.** 컨테이너 헬스체크에 `wget --spider`를 쓰면 왜 위험한가? 브라우저로는 200이 나오는 이유와, 어떻게 고치는지 답하라.

**1-14.** `Cpu: 512`에서 허용되는 메모리 값은 무엇인가? `Memory: 512`는 되는가? 잘못된 조합을 썼을 때 실패가 언제 드러나는가?

**1-15.** `DesiredCount`, `MinimumHealthyPercent`, `MaximumPercent`로 배포 중 태스크 수의 최소·최대를 구하는 식을 쓰라. 두 식의 반올림 방향이 다른 이유는?

**1-16.** 롤링 업데이트의 두 퍼센트 기본값은? `DesiredCount: 1`에서 `MaximumPercent: 100`이면 무슨 일이 일어나고 증상은 어떻게 나타나는가?

**1-17.** 배포 서킷 브레이커의 실패 임계값 계산식을 쓰고, `DesiredCount`가 1·25·400·800일 때의 값을 각각 구하라. 실패 카운트가 초기화되는 조건은?

**1-18.** 첫 배포가 실패했는데 서킷 브레이커가 롤백하지 않는다. 왜인가? 이때 함께 사라지는 것과, 예방책을 답하라.

**1-19.** Fargate Spot의 할인율, 회수 시 경고 시간과 신호, `stopTimeout`의 기본값·최대값을 답하라. 태스크 1개 서비스에서 회수되면 어떻게 되는가?

**1-20.** ECS Exec 권한은 어느 롤에 넣는가? 그 이유와, 함께 쓸 수 없는 설정, 그리고 도는 태스크에 대한 제약을 답하라.

### 묶음 C — IAM·시크릿·알람·배포 (문서 05~08)

**1-21.** IAM 롤에 붙는 두 문서는 각각 무엇을 정하는가? AccessDenied가 났을 때 어느 쪽을 먼저 보고, 두 경우의 오류 발생 단계는 어떻게 다른가?

**1-22.** 실행 롤과 태스크 롤을 가르는 기준은 무엇인가? 컨테이너 안 코드는 어느 쪽을 쓰는가? 두 롤의 신뢰 정책이 같은데도 나누는 이유는?

**1-23.** 실행 롤에 `AmazonECSTaskExecutionRolePolicy`를 붙였는데 태스크가 `ResourceInitializationError: unable to pull secrets`로 죽는다. 원인과 해결책, 그리고 이 함정이 흔한 이유를 답하라.

**1-24.** 배포 파이프라인이 `RegisterTaskDefinition`에서 AccessDenied를 받는다. 어느 롤의 무슨 권한이 없는가? 함께 걸어야 하는 조건과 그것이 막는 공격 경로는?

**1-25.** `Secrets`로 주입된 값은 언제 해석되는가? 시크릿 값을 갱신하면 도는 컨테이너는 어떻게 되고, 무엇을 해야 반영되는가? 이 성질이 "회전이 필요한 값"에 어떤 제약을 만드는가?

**1-26.** 시크릿 초기값을 빈 문자열이 아니라 표식 문자열로 두는 이유 두 가지를 답하라. 값을 주입한 뒤 그 리소스 블록의 `Description`만 고쳐 배포하면?

**1-27.** `TreatMissingData`의 기본값과 그 결과를 답하라. 지표 성격에 따라 무엇을 골라야 하는지 판단 기준을 쓰고, 반대로 골랐을 때 각각 어떤 일이 일어나는지 답하라.

**1-28.** OIDC 신뢰 정책에서 `sub` 조건을 빼면 무엇이 가능해지는가? `sub`의 두 형식과 `aud` 값, 그리고 워크플로에 필요한 권한 선언을 답하라.

**1-29.** 가변 태그(`dev`)만 쓰면 무엇이 막히는가? 같은 태그에 새 이미지를 push했는데 서비스가 옛 코드를 돌리는 이유와 해결책은?

# 파트 2. 판단 문제 (시나리오)

> 해설: [93-solutions.md](93-solutions.md) 파트 2

**2-1.** 이 서비스를 STAGE 환경으로 확장한다. 부하 시험을 돌리고 운영 직전 검증을 하는 환경이며, 낮 시간에는 QA 인원이 상시 사용한다.

`DesiredCount`, 용량 공급자 전략(`FARGATE` / `FARGATE_SPOT`의 `Base`·`Weight`), `MinimumHealthyPercent`/`MaximumPercent`를 정하고 각각의 근거를 쓰라. **Spot 비중을 지금(100%)보다 높게 유지하는 것이 오히려 나은 조건은 무엇인지도 함께 적으라.**

**2-2.** 장애 감지가 최대 90초 걸리는 것이 느리다는 의견이 나왔다. `HealthCheckIntervalSeconds: 10` / `UnhealthyThresholdCount: 2`로 바꾸면 감지가 20초로 줄어든다.

이 변경에 찬성하는가 반대하는가? 근거를 쓰고, **반대 선택이 더 나은 조건**을 함께 적으라. 이 서비스가 관리 API라는 사실이 판단에 어떻게 들어가는가?

**2-3.** 새 기능이 외부 결제 API의 API 키를 필요로 한다. 이 키는 6개월마다 사람이 콘솔에서 재발급하며, 유출되면 결제 요청을 위조할 수 있다.

이 값을 (a) CloudFormation 파라미터 + `Environment` 평문, (b) SSM Parameter Store, (c) Secrets Manager 중 어디에 둘 것인가? 선택과 근거를 쓰고, **이 템플릿이 DB 비밀번호와 Graph 토큰을 다르게 취급한 기준을 이 결정에 어떻게 적용했는지** 밝히라.

**2-4.** 컨테이너 메모리 사용률 알람을 추가한다. 지표는 `ECS/ContainerInsights`의 `MemoryUtilized`이고, 임계값은 80%로 정했다.

`TreatMissingData`를 무엇으로 설정할 것인가? 판단 근거를 쓰고, **반대로 설정했을 때 실제로 무슨 일이 일어나는지** 구체적으로 적으라. 이 알람이 의존하는 클러스터 설정은 무엇인가?

**2-5.** 이 서비스가 PROD로 가면서 트래픽이 초당 200요청 수준이 된다. 현재 로그 드라이버는 `mode: blocking`이다.

`non-blocking`으로 바꿀 것인가? 근거를 쓰고, **바꾸지 않는 것이 나은 조건**을 함께 적으라. 이 결정이 장애 조사에 어떤 영향을 주는가?

**2-6.** 현재 태스크 정의는 배포 파이프라인이 소유한다(새 리비전을 등록하고 서비스를 갱신). 팀원이 "CloudFormation이 모든 것을 소유하게 하면 드리프트가 없어져서 낫다"고 제안한다.

찬성하는가 반대하는가? 두 방식의 대가를 각각 쓰고, **제안이 더 나은 조건**을 적으라. 현재 방식을 유지할 때 반드시 지켜야 하는 규율은 무엇인가?

**2-7.** PROD 배포 롤을 만든다. OIDC `sub` 조건을 `repo:my-org/orders-server:environment:prod`로 할지, `repo:my-org/orders-server:ref:refs/heads/main`으로 할지 결정해야 한다.

어느 쪽을 고르고 왜인가? **브랜치 스코프가 더 나은 조건이 있는지**도 답하라. 두 방식에서 "승인 없이 PROD에 배포"를 막는 지점이 각각 어디인가?

# 파트 3. 재현 과제 (직접 만들기)

> 판정 기준: [93-solutions.md](93-solutions.md) 파트 3

**3-1.** 백지에서 최소 ECS Fargate 서비스 CloudFormation 템플릿을 작성하라. 실제 배포는 하지 않는다 — 문법과 구조가 목표다.

- 성공 기준
  - [ ] 리소스 8종이 있다: 로그 그룹 / 실행 롤 / 태스크 롤 / ALB 보안 그룹 / 서비스 보안 그룹 / 타겟그룹 / 태스크 정의 / 서비스
  - [ ] 서비스 보안 그룹의 인그레스가 **ALB 보안 그룹을 참조**한다 (IP가 아니다)
  - [ ] 두 롤의 신뢰 정책에 `ecs-tasks.amazonaws.com`이 있다
  - [ ] 태스크 정의가 `!GetAtt`로 두 롤의 **ARN**을 가져온다 (`!Ref`가 아니다 — 왜인지 설명할 수 있어야 한다)
  - [ ] `Cpu`/`Memory`가 유효한 조합이다
  - [ ] 로그 그룹에 `RetentionInDays`가 있다
  - [ ] 교체를 유발할 수 있는 리소스에 고정 이름이 없고, `Name` 태그로 식별한다
  - [ ] 이미지 URI가 의사 파라미터(`AWS::AccountId`·`AWS::Region`)로 조립된다
  - [ ] `cfn-lint`를 돌릴 수 있으면 통과한다 (없으면 YAML 파서로 문법만 확인)
- 소요 예상: 40~60분
- 막히면: `01-iac-and-cloudformation.md` § 템플릿의 여섯 섹션, `04-ecs-fargate.md` § 컨테이너 정의 읽기

**3-2.** 아래 세 증상에 대해 **진단 경로**를 각각 작성하라. "무엇을 어떤 순서로 확인하고, 각 단계에서 어떤 결과가 나오면 다음으로 넘어가는가"를 적는다.

1. 브라우저에서 접속하니 503이 반환된다
2. 태스크가 기동 → unhealthy → 교체를 반복한다
3. 배포가 시작됐는데 20분째 진행되지 않는다

- 성공 기준
  - [ ] 각 증상마다 확인 단계가 **순서대로** 3개 이상 있다
  - [ ] 각 단계에 "무엇을 보는가"(콘솔 화면·CLI 명령·로그)가 구체적으로 적혀 있다
  - [ ] 각 단계에 **분기 조건**이 있다 (이 결과면 여기로, 아니면 저기로)
  - [ ] 세 증상의 경로가 서로 다르다 (같으면 증상 구분을 못 한 것이다)
  - [ ] 증상 3의 경로에 배포 설정(두 퍼센트) 확인이 들어 있다
- 소요 예상: 30~40분
- 막히면: `03-alb-and-target-group.md` § 요청이 컨테이너에 도달하는 전체 경로, `04-ecs-fargate.md` § 증상별 원인 표

**3-3.** 이 템플릿의 **보안 그룹 체인과 트래픽 경로를 다이어그램으로** 그리라. 손그림·ASCII·다이어그램 도구 무엇이든 좋다.

- 성공 기준
  - [ ] 인터넷 / public 서브넷 / private 서브넷 / DB의 네 영역이 구분돼 있다
  - [ ] 보안 그룹 3개와 각각의 인그레스 출발지·포트가 표시돼 있다
  - [ ] 화살표마다 포트 번호가 있다 (443 / 8080 / 3306)
  - [ ] ALB가 public에, 태스크가 private에 있고 그 이유를 한 줄로 적었다
  - [ ] 태스크가 밖으로 나가는 경로(NAT)와 그것이 필요한 이유 2가지가 표시돼 있다
  - [ ] 사무실·VPN IP가 어디에서 걸러지는지 표시돼 있다
- 소요 예상: 20~30분
- 막히면: `02-network-vpc-sg.md` § SG 체인

### 특히 자주 틀리는 자리

아래는 이 주제에서 **기본값과 직관이 어긋나는** 지점이다. 틀렸다면 "부주의"가 아니라 "오해"로 분류할 값어치가 있다.
