# 90. 암기 필수 카드

검색 없이 즉답해야 하는 것만 모았다. 설계·판단을 가르는 경계, 불변 트레이드오프, 진단 신호에 한정한다.

## 정의 — 이 한 문장을 못 대면 나머지가 흔들린다

- [ ] **일관성의 종류가 이 시리즈의 주제다:** 트랜잭션 일관성(중간 과정과 결과 모두 일관) ↔ **결과적 일관성**(결과적으로는 보장되나 **중간에 어긋난 구간이 발생**).
- [ ] **`eventual consistency` = "언젠가는 일관성이 달성된다".** "결과적 일관성"보다 이 번역이 감을 준다.
- [ ] **애그리게이트 = 불변식의 단위.** 애그리게이트가 주인공이 아니라 **불변식이 주인공**이고, 불변식이 객체들을 묶은 결과가 애그리게이트다.
- [ ] **불변식 = 도메인에서 "발견된" 규칙.** 절대적이지 않아 **도메인이 변하면 변한다**(스프린트마다 박살나는 게 정상).
- [ ] **엔티티 ↔ 값 객체의 차이는 식별 방식뿐이다.** DDD 원론에 **불변성 규정은 없다.**
- [ ] **팩트(fact) = 이미 확정된 사실.** 과거형 이벤트가 이것이고, 도메인 용어다.
- [ ] **분산 트랜잭션 = 애그리게이트 간 트랜잭션.** 네트워크 너머인지 한 프로세스 안인지는 무관하다.

## 불변 트레이드오프 — 모르면 잘못된 선택을 반복한다

- [ ] **애그리게이트를 작게 ↔ 크게:** 작으면 부분 연산이 쉽고 트랜잭션 구간이 짧지만 **애그리게이트 간 통신(도메인 이벤트)이 기하급수적으로 늘어난다.** 그 관리 방법이 이벤트 소싱이고 책 전체의 줄기다.
- [ ] **엔티티 ↔ 값 객체:** 값 객체는 **유지보수 비용이 낮고**(불변성이 아니라 **식별되지 않아 참조될 수 없어서**), 엔티티는 **일관성 관리가 쉽다**(변화에도 참조 무결성 유지).
- [ ] **명령 ↔ 이벤트:** 스펙트럼이다. 강할수록 수신자 재량이 없고 결합이 늘며, 약할수록 **여파를 예측할 수 없다**(200개 날렸는데 수신 쪽이 뭘 하는지 모른다).
- [ ] **OCP를 적용 ↔ 안 함:** 적용하면 함수가 수정에 닫히지만 **분기 책임=비즈니스 책임이 클라이언트로 이전**된다. if 떡칠 함수는 신입도 전문가로 만들고, 전략 객체 3층은 호출자를 전문가로 요구한다.
- [ ] **관계형 테이블 분리 ↔ 한 테이블 JSON:** 분리는 일괄 갱신이 쉽고, JSON은 **트랜잭션이 사라진다**(테이블 하나는 원래 트랜잭션이 보장됨). 값 복제의 갱신 비용이 대가다.
- [ ] **어댑터에 지식을 둠 ↔ 서비스로 뺌:** 어댑터에 노하우가 쌓이면 **"갈아치울 수 있는 어댑터"라는 전제가 깨진다.**
- [ ] **PGMQ(RDB 큐) ↔ 카프카:** 전자는 운영 대상이 늘지 않고 **같은 트랜잭션에서 발행**할 수 있어 아웃박스가 불필요하다. 후자는 스트리밍 처리량을 준다.

## 의사결정 경계 — 설계 순간에 즉시 필요

- [ ] **경계는 애그리게이트다: 내부 = 상시 불변식 / 간 = 언젠가 달성.** **이것만 이해하면 나머지 기술 내용은 따라온다.** MSA만의 문제가 아니고 한 프로세스 안에서도 같다.
- [ ] **트랜잭션 범위를 줄이는 유일한 방법은 불변식 그룹의 크기·개수를 줄이는 것.** 다른 방법은 없다.
- [ ] **애그리게이트 크기의 정답은 없다 — 개발자가 정한다.** 단 실무에서는 **바운디드 컨텍스트(팀)가 더 세서** 애그리게이트를 쪼개서라도 경계가 생긴다.
- [ ] **애그리게이트 루트는 엔티티, 내부 객체는 자유(값 객체 가능).** 내부 객체는 의존성이 안에 갇혀 대외 참조가 없다.
- [ ] **사가는 낙관성을 전제한다.** 자주 실패할 것(회원 가입 아이디 중복 등)은 **애초에 만들면 안 된다.**
- [ ] **낙관성은 성격이 아니라 조정한 결과다.** 높이는 방법: **충돌 대상 좁히기 / 트랜잭션 주체 제한 / 사전 티켓 발급 / 사본을 통해 전개.**
- [ ] **페널티 강도로 판단한다: 재고(약함) ↔ 결제(강함).** 데드라인은 **약한 페널티를 암묵적으로 가정**한다.
- [ ] **REST 서비스라면 토큰, 브라우저 대상이면 쿠키.** 세션이 등장하면 REST가 아니다.

## 구현 규칙 — 어기면 나중에 전면 재작업

- [ ] **재수화가 가능하려면 현재 상태가 오직 이벤트의 적용 결과여야 한다** → 상태를 바꾸는 공개 메서드가 있으면 안 되고 **입구는 커맨드를 받는 메서드 하나**다.
- [ ] **이벤트 소싱의 애그리게이트 루트 = 커맨드 패턴의 Invoker.** 리플렉션 없이 디스패치를 푸는 방법이다.
- [ ] **리플레이 중에는 적용한 커맨드를 다시 쌓지 않는다** — 쌓으면 다음 저장에서 **같은 이벤트가 중복**돼 로그가 오염된다.
- [ ] **restore는 빈 객체에만 가능하다.** 이미 커맨드가 쌓인 객체는 복원 대상이 아니다.
- [ ] **과거형 이벤트는 확정 후에 발급한다** — DB 트랜잭션·네트워크 호출이 끝난 뒤. 실무에서 자주 깨진다.
- [ ] **불변식 유지의 일반 구현: 사본 → 로직 → 불변식 검사 → 통과 시 반영**(아카이빙). 귀찮아서 모든 메서드에 전체 불변식을 적용하는 것이 보통이다.
- [ ] **애그리게이트 내부 객체를 외부에 노출하지 않는다** — 노출하면 불변식을 우회한다. 불변식 적용 대상이 루트이기 때문이다.
- [ ] **서비스 간 DTO는 수신 측이 임의로 정의하지 않는다.** 스펙을 양쪽 밖(공개 스키마)에 두고 참조한다.

## 진단 신호 — 증상을 원인에 즉시 매핑

- [ ] **에러도 예외도 없는데 결과가 "없음"으로 나온다** → **컨텍스트 에러.** 수신 측이 임의로 정의한 DTO와 실제 응답이 어긋난 것이고, 컴파일·런타임 어디서도 안 잡힌다.
- [ ] **필드가 `"null"` 문자열이나 의미 없는 기본값으로 채워져 온다** → 수신 측 스펙을 맞추려고 **암묵적 null 필드**를 내보낸 것. 같은 팀 안에서도 발생한다.
- [ ] **클라이언트가 응답 코드 분기 때문에 로직이 쪼개진다** → 상태 코드를 잘게 쓴 결과. 클라는 대개 **200만 본다.**
- [ ] **사가가 끝없이 대기한다** → 메시지 시스템은 **타임아웃을 알려주지 않는다.** 데드라인은 상대 사정을 모른 채 내가 끊는 것이다.
- [ ] **재수화했더니 상태가 다르다** → 이벤트 외의 경로로 상태를 바꾼 메서드가 있거나, 리플레이 중 커맨드를 다시 쌓았다.
- [ ] **보상 절차가 상시로 돌고 있다** → 낙관성이 낮은 대상을 분산 트랜잭션으로 만든 것. 범위를 좁히거나 그 기능을 분산에서 뺀다.

## 조직·판단 — 코드보다 먼저 오는 것

- [ ] **바운디드 컨텍스트를 실제로 정하는 것은 조직과 정치다.** 커뮤니케이션이 어려우면 나누고, 도메인이 같아도 정치적으로 필요하면 나눈다.
- [ ] **"도메인 전문가"는 대개 존재하지 않는다** — 도메인 수행자가 있고, 분석을 마친 개발자가 전문가가 되는 경우가 태반이다.
- [ ] **DDD의 전제는 "소통 비용 > 코드·기계 비용"이다.** 대규모 SI 배경에서 나왔고 도메인이 빠르게 바뀌는 소규모 조직에는 과할 수 있다.
- [ ] **DDD의 목표는 확장성이 아니라 "도메인이 바뀐 만큼만 코드가 바뀌게" 하는 것.**
- [ ] **트랜잭션 일관성이 필요하다고 믿은 구간이 대부분 아니다** — 사람이 하는 일이기 때문이다. **회계장부조차** 감사 수정 지시로 맞춰진다.
- [ ] **기획·실무자는 상상 속 이상향을 말한다.** "정말 그렇게 하냐"고 파고들어야 진짜 요구가 나온다.
- [ ] **큰 기업은 강한 페널티마저 비용으로 떨구고 약한 페널티로 바꾼다** — 쿠팡의 선결제·구매 완료 선처리가 그 예다.

## 알면 좋지만 암기 대상 아님 (원리로 유도 가능)

- 오케스트레이션 엔진 제품명(Conductor·Temporal·Cadence·Airflow·Axon·NServiceBus) — **네 부류의 성격**만 알면 된다
- PGMQ의 이미지 태그·지원 버전 — 공식 저장소에서 확인한다
- 카프카 설치·운영 절차 — 책과 공식 문서의 영역이다
