# 01. 컴퓨터 한 대에서 시작하기

## 이 장에서 배울 것

프로그램을 실행할 때 컴퓨터 안에서 무슨 일이 생기는지 설명한다. 컴퓨터 내부를 배운 적이 없다고 가정한다. 인터넷과 AWS는 아직 몰라도 된다.

## 출발 상황 — 연필을 주문하는 프로그램

작은 문구점의 주문 서비스를 만든다고 하자. 사용자가 연필 한 자루를 주문하면 프로그램은 남은 수량을 확인하고 주문을 기록해야 한다. 이 일을 시키려면 먼저 프로그램을 컴퓨터에서 실행해야 한다.

프로그램은 컴퓨터가 수행할 명령을 표현한 것이다. “남은 수량을 읽는다”, “수량이 충분하면 하나를 뺀다”, “결과를 저장한다”처럼 작업 순서와 조건을 담는다. 프로그래밍 언어는 이런 명령을 작성하기 위한 표현 방법이다.

이 교재에서는 코드를 작성할 줄 몰라도 된다. 대신 **명령, 실행 중인 값, 저장된 결과가 어디에 있는지** 구분해 보자.

## 1. 명령을 수행하는 CPU

CPU는 컴퓨터의 명령을 실행하는 장치다. 값을 더하고, 두 값을 비교하고, 조건에 따라 다음에 실행할 명령을 고르는 일 등을 수행한다.

주문 프로그램이 “남은 수량이 주문 수량보다 크거나 같은가?”를 판단할 때도 결국 값을 읽고 비교하는 명령이 실행된다. 화면에 “주문 성공”이라고 표시하는 일도 여러 명령의 실행 결과다.

CPU가 빠르면 모든 작업이 같은 비율로 빨라지는 것은 아니다. 주문 결과를 다른 컴퓨터에서 받아야 한다면 그 응답을 기다리는 시간도 있기 때문이다. 기다림과 계산의 차이는 06장에서 다시 다룬다.

## 2. 작업 중인 값을 두는 메모리

메모리는 실행 중인 프로그램의 명령과 데이터를 놓는 공간이다. 여기서 말하는 메모리는 주로 RAM이다. CPU는 실행에 필요한 값에 접근하며 작업한다.

예를 들어 지금 처리하는 주문의 상품 번호, 주문 수량, 계산 중인 금액을 메모리에 둘 수 있다. 책상 위에 현재 작업할 서류를 펼쳐 놓는 모습과 비교해 볼 수 있다.

RAM의 내용은 전원이 사라지면 유지되지 않는다. 따라서 주문을 메모리에만 두고 컴퓨터를 껐다면, 그 주문을 나중에 다시 확인할 수 있다고 기대하면 안 된다.

## 3. 나중에도 꺼낼 파일을 두는 저장 장치

SSD 같은 저장 장치는 전원이 꺼진 뒤에도 데이터를 보관하도록 만든 장치다. 프로그램 파일, 사진, 저장한 문서 등이 여기에 놓인다.

메모리가 작업 책상이라면 저장 장치는 서류 보관함에 가깝다. 프로그램을 실행할 때 필요한 명령과 데이터를 메모리로 가져오고, 작업한 결과를 나중에도 남겨야 한다면 저장 장치에 기록한다.

이 비유가 메모리와 저장 장치의 모든 차이를 나타내지는 않는다. 지금은 **작업 중에 사용하는 공간과 전원 종료 후에도 남겨야 하는 공간을 구분하는 데** 사용한다. 저장 장치도 고장 날 수 있으므로 오래 남는다는 말과 영원히 안전하다는 말은 다르다.

## 4. 0과 1은 왜 나오는가

컴퓨터는 데이터를 비트라는 단위로 표현한다. 비트 하나는 0 또는 1 두 상태 중 하나를 나타낸다. 비트 8개를 모으면 1바이트라고 한다.

비트 하나로는 두 가지, 두 개로는 `00`, `01`, `10`, `11`의 네 가지를 구분할 수 있다. 비트가 하나 늘 때마다 구분할 수 있는 조합은 두 배가 된다. 따라서 비트 8개의 조합 수는 `2⁸ = 256`이다.

숫자, 글자, 이미지도 정해진 규칙으로 이런 값들에 대응시킨다. 예를 들어 글자와 숫자를 대응시키는 규칙을 정해야 컴퓨터가 저장한 값을 다시 글자로 읽을 수 있다. 이 대응 규칙을 **인코딩**이라고 한다. 지금 특정 인코딩 표를 외울 필요는 없다.

## 5. 여러 프로그램이 함께 실행되면 누가 정리할까

우리는 주문 프로그램만 실행하지 않는다. 브라우저로 웹사이트를 보고, 음악을 재생하고, 파일도 저장한다. 이 프로그램들은 CPU, 메모리, 저장 장치 등을 함께 사용한다.

**운영체제(OS)**는 이런 자원을 관리하고 프로그램이 장치를 사용할 수 있게 돕는 기본 소프트웨어다. Windows, macOS, Linux가 예다. 어떤 프로그램에 CPU를 사용할 차례를 줄지, 메모리를 어떻게 관리할지, 파일 접근을 허용할지 등을 다룬다.

앱이 파일을 읽거나 네트워크로 데이터를 보낼 때도 운영체제가 제공하는 기능을 사용한다. 앱이 컴퓨터의 모든 장치를 제멋대로 직접 다루게 두는 방식과는 다르다.

## 6. 저장된 프로그램과 실행 중인 프로세스

저장 장치에 있는 프로그램 파일을 실행하면 운영체제는 실행에 필요한 상태와 자원을 준비한다. **프로세스**는 이렇게 실행 중인 프로그램의 단위다.

같은 프로그램을 두 번 실행해 프로세스 A와 B를 만들 수 있다. 두 프로세스의 명령은 같아도 지금 처리하는 주문이나 작업 중인 값은 다를 수 있다. A의 메모리에 적은 주문 수량이 B의 메모리에 저절로 나타나는 것은 아니다.

| 대상 | 무엇을 뜻하는가 | 주문 프로그램의 예 |
|---|---|---|
| 프로그램 파일 | 실행할 명령을 담아 저장한 것 | 아직 실행하지 않은 주문 프로그램 |
| 프로세스 | 실행 중인 프로그램과 그 상태 | 주문 42를 처리 중인 실행 인스턴스 |
| 업무 데이터 | 프로그램이 다루는 사실과 값 | 주문 42의 상품과 수량 |

프로세스를 종료한 뒤 새로 실행해도 이전 실행의 작업 중인 메모리가 자동으로 이어지지는 않는다. 다시 필요할 업무 데이터는 별도로 저장하고 읽는 방법을 마련해야 한다.

## 배포와 처음 연결하기

배포는 프로그램을 실행할 곳에 전달하고 실제로 사용할 수 있게 적용하는 일이다. 프로그램 파일을 복사하는 것만으로 주문을 받을 준비가 끝나지는 않는다. 프로세스를 실행해야 하고, 필요한 데이터와 설정도 준비해야 한다.

AWS를 사용해도 이 관계는 남는다. 누군가는 명령을 실행하고, 메모리를 사용하며, 남겨야 할 데이터를 저장해야 한다. 플랫폼은 그 준비와 관리를 맡는 방법을 바꾼다.

## 꼭 기억할 것

- **카드 01:** CPU는 명령 실행, 메모리는 작업 중인 명령·데이터, 저장 장치는 전원 종료 후에도 남길 데이터의 보관을 맡는다.
- **카드 02:** 프로그램 파일과 실행 중인 프로세스는 다르다. 같은 프로그램의 두 프로세스는 작업 상태가 저절로 공유되지 않는다.

## 자가 진단

<details><summary>주문을 메모리에만 기록하면 컴퓨터 전원을 껐다 켰을 때 어떻게 될까?</summary>

RAM의 내용은 전원 종료 후 유지되지 않는다. 그 주문을 다시 읽으려면 전원 종료 후에도 남는 저장소에 기록했어야 한다.
</details>

<details><summary>같은 프로그램을 두 번 실행하면 처리 중인 주문도 같아야 할까?</summary>

아니다. 같은 명령을 실행해도 각 프로세스가 받은 입력과 작업 상태는 다를 수 있다. 둘의 메모리 값도 자동으로 공유되지 않는다.
</details>

<details><summary>CPU를 더 빠르게 바꾸면 다른 컴퓨터의 응답을 기다리는 시간도 반드시 줄까?</summary>

그렇지 않다. 내 컴퓨터의 명령 실행 속도와 상대 응답을 기다리는 시간은 다른 요소다.
</details>
