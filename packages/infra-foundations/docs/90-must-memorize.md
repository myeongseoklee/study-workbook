# 암기 카드 — 처음 배운 원리를 다시 꺼내 쓰기

본문의 여러 개념 중 즉시 구분해야 할 관계 18개를 골랐다. 장별 개수를 똑같이 맞추기보다 독립된 이해 단위를 기준으로 삼았다. 워크북 파트 1의 문항 1-1~1-18과 순서대로 대응한다.

### 카드 01

CPU는 명령 실행, 메모리는 작업 중인 명령·데이터, 저장 장치는 전원 종료 후에도 남길 데이터의 보관을 맡는다.

되짚기: [01장](01-computers-and-programs.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 02

프로그램 파일과 실행 중인 프로세스는 다르다. 같은 프로그램의 두 프로세스는 작업 상태가 저절로 공유되지 않는다.

되짚기: [01장](01-computers-and-programs.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 03

IP 주소는 네트워크에서 보낼 주소를, 포트는 그 주소의 통신 끝점을 구분한다. 앱은 수신 대기를 시작해야 연결을 받을 수 있다.

되짚기: [02장](02-addresses-and-packets.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 04

DNS는 이름에 대응하는 정보를 찾고, HTTP는 요청과 응답의 형식·의미를 정한다. 주소를 찾은 것과 업무를 처리한 것은 다르다.

되짚기: [03장](03-dns-and-http.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 05

TCP는 순서 있는 바이트 전달을, TLS는 상대 검증과 통신 보호를 맡는다. 어느 쪽도 주문의 업무 결과를 대신 판단하지 않는다.

되짚기: [04장](04-tcp-and-tls.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 06

라우팅은 어디로 보낼지, 방화벽은 통신을 허용할지 판단한다. 왕복 경로와 앱의 수신도 함께 성립해야 한다.

되짚기: [05장](05-routing-and-access.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 07

요청의 시간에는 계산과 대기가 함께 있다. 비동기는 대기 중 다른 일을 진행하게 할 수 있지만 계산 자원을 저절로 늘리지 않는다.

되짚기: [06장](06-processes-and-concurrency.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 08

이미지는 실행에 사용할 파일·기본 설정이고, 컨테이너는 그것을 바탕으로 관리하는 별도 실행 환경이다. 실행 중 프로세스 메모리·컨테이너 파일 변경·연결한 볼륨의 수명은 다르다.

되짚기: [07장](07-containers-and-images.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 09

앱의 실행 상태와 영속 데이터는 수명이 다르다. 다시 실행한 앱도 필요한 업무 데이터를 찾아 읽을 수 있어야 한다.

되짚기: [08장](08-storage-and-databases.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 10

트랜잭션은 정한 경계 안의 변경을 함께 확정하거나 취소한다. 내 DB 밖의 결제 효과까지 자동으로 되돌리지는 않는다.

되짚기: [09장](09-transactions-and-recovery.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 11

앱을 여러 개로 늘리려면 요청 분배뿐 아니라 상태의 공유와 수명, 공통 의존성의 용량, 함께 실패하는 범위를 확인한다.

되짚기: [10장](10-scaling-and-state.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 12

시간 초과는 원격 업무 실패의 증명이 아니다. 재시도에는 결과 확인과 중복 효과 방지, 횟수·시간·부하 제한이 함께 필요하다.

되짚기: [11장](11-timeouts-and-retries.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 13

캐시는 원본 접근을 줄이는 대신 오래된 값을 다루고, 큐는 작업을 나누는 대신 완료 지연·적체·재전달을 다룬다.

되짚기: [12장](12-caches-and-queues.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 14

새 대상이 준비된 뒤 요청을 옮기고, 이전 대상의 새 요청 배정을 멈춘 뒤 진행 중 일을 마무리한다. 프로세스 실행·준비·드레이닝·종료는 다른 사건이다.

되짚기: [13장](13-deployment-and-shutdown.md). 이 문장을 외운 뒤 예제의 중간 상태도 자기 말로 설명한다.

### 카드 15

코드와 데이터 구조는 함께 변한다. 새 형식을 추가하고 사용자를 옮긴 뒤, 공존과 롤백에 필요 없다는 근거가 생겼을 때 옛 형식을 제거한다.

### 카드 16

메트릭으로 영향과 범위를 찾고 로그·추적으로 실제 요청과 대기 구간을 확인한다. 평균과 CPU 하나로 사용자 경험이나 원인을 확정하지 않는다.

인증은 주체 확인, 인가는 작업 허용 판단이다. 네트워크 도달·TLS 상대 확인·앱 사용자 권한은 서로 대신하지 않는다.
