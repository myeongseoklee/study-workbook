# 용어 해설집 — 개념이 이어지는 순서로 찾기

본문에서 처음 등장하는 용어는 그 자리에서 설명했다. 이 파일은 다시 만난 이름을 찾고, 어떤 문제를 풀기 위해 배웠는지 되짚는 보조 자료다. 정의만 외워 막혔다면 연결된 장의 예제까지 돌아간다.

## 1. 실행 — 명령이 작업 상태를 만든다

프로그램 파일을 실행하면 프로세스가 생긴다. CPU가 명령을 수행하고 메모리에 작업 상태를 둔다. 여러 일이 자원을 나눠 쓰므로 실행 차례와 대기를 다룬다.

| 용어 | 뜻과 작동의 연결 | 다시 읽을 곳 |
|---|---|---|
| 비트·바이트 | 비트는 0 또는 1, 바이트는 8비트다. 비트 수가 하나 늘면 표현 조합은 두 배가 된다 | [01](01-computers-and-programs.md) |
| 인코딩 | 글자 같은 대상을 값으로 표현하는 대응 규칙이다. 같은 규칙을 알아야 저장한 값을 다시 읽는다 | [01](01-computers-and-programs.md) |
| CPU | 명령을 실행하는 장치다. 비교·계산을 수행하지만 외부 응답 시간까지 결정하지는 않는다 | [01](01-computers-and-programs.md) |
| 메모리·RAM | 실행 중 명령과 값을 사용하는 공간이다. 전원 종료 후 보관할 데이터와 구분한다 | [01](01-computers-and-programs.md) |
| 저장 장치 | 전원 종료 뒤에도 보관할 데이터를 기록하는 장치다. 고장과 복구는 별도다 | [01](01-computers-and-programs.md) |
| 운영체제 | CPU·메모리·장치 등 자원을 관리하고 프로그램이 사용할 기능을 제공하는 기본 소프트웨어다 | [01](01-computers-and-programs.md) |
| 프로그램·프로세스 | 명령을 담은 파일과 그 명령을 실행 중인 단위의 차이다. 같은 프로그램도 실행 상태는 다를 수 있다 | [01](01-computers-and-programs.md) |
| 스케줄링 | 실행 가능한 작업에 CPU 차례를 배정하는 일이다. 대기 중인 작업과 실행 중인 작업을 구분한다 | [06](06-processes-and-concurrency.md) |
| 입출력·I/O | 디스크·네트워크 등과 데이터를 주고받는 작업이다. 대기는 계산 시간과 다를 수 있다 | [06](06-processes-and-concurrency.md) |
| 스레드 | 프로세스 안의 실행 흐름이다. 같은 메모리를 공유해 동시 접근의 조정이 필요할 수 있다 | [06](06-processes-and-concurrency.md) |
| 동시성·병렬성 | 여러 일을 진행 중으로 다루는 것과 실제 같은 시간에 실행하는 것의 차이다 | [06](06-processes-and-concurrency.md) |
| 비동기 | 완료를 기다리는 동안 다른 일을 진행하고 나중에 이어 처리하는 방식이다. CPU를 저절로 늘리지는 않는다 | [06](06-processes-and-concurrency.md) |
| 시그널·PID | 프로세스에 사건을 알리는 수단과 실행 프로세스를 구분하는 번호다 | [06](06-processes-and-concurrency.md) |

## 2. 통신 — 주소를 찾고 연결한 뒤 요청의 뜻을 전달한다

패킷의 목적지를 정하고 중간에서 전달한다. 도착한 컴퓨터에서는 받을 프로그램이 필요하다. 그 위에서 메시지 형식, 전달 순서, 보호를 각각 약속한다.

| 용어 | 뜻과 작동의 연결 | 다시 읽을 곳 |
|---|---|---|
| 네트워크·패킷 | 데이터를 교환하도록 연결한 구성과, IP 계층에서 전달하는 단위다. 데이터가 나뉘면 누락과 순서를 다뤄야 한다 | [02](02-addresses-and-packets.md) |
| IP 주소·포트 | 네트워크의 주소와 그 주소의 통신 끝점을 구분한다. 같은 IP에도 여러 포트의 앱이 있을 수 있다 | [02](02-addresses-and-packets.md) |
| 소켓·수신 대기 | 앱이 운영체제의 통신 기능을 쓰는 인터페이스와, 연결을 받을 준비를 한 상태다 | [02](02-addresses-and-packets.md) |
| 루프백·localhost | 자기 네트워크 환경의 자기 자신으로 통신하는 주소와 이름이다. 다른 컴퓨터 주소가 아니다 | [02](02-addresses-and-packets.md) |
| 프로토콜 | 통신의 형식과 동작에 관한 약속이다. 데이터의 전달 방식과 업무 의미는 다른 약속일 수 있다 | [03](03-dns-and-http.md) |
| 클라이언트·서버 | 요청을 보내는 쪽과 받아 응답하는 쪽의 역할이다. 특별한 외형의 컴퓨터 이름만은 아니다 | [03](03-dns-and-http.md) |
| DNS·리졸버 | 이름의 정보를 찾는 분산 체계와 그 조회를 수행하는 서버다. 이름 조회 뒤 실제 연결이 더 필요하다 | [03](03-dns-and-http.md) |
| 레코드·TTL | DNS가 제공하는 종류별 정보와 캐시 수명이다. 변경 전 결과가 잠시 남을 수 있는 이유다 | [03](03-dns-and-http.md) |
| HTTP | 요청과 응답의 형식·의미를 정하는 프로토콜이다. 메서드·경로·헤더·본문을 구분한다 | [03](03-dns-and-http.md) |
| TCP·스트림 | 바이트의 위치와 수신을 관리해 순서 있는 흐름을 제공한다. 앱의 메시지 경계와 업무 결과는 별도다 | [04](04-tcp-and-tls.md) |
| TLS·인증서 | 상대 확인과 통신 보호를 제공하는 체계와 이름·키의 신뢰 관계를 확인하는 데 쓰는 정보다 | [04](04-tcp-and-tls.md) |
| 라우터·라우팅 테이블 | 다음 전달을 고르는 장치와 목적지별 규칙이다. 맞는 대역 중 더 구체적인 경로를 고른다 | [05](05-routing-and-access.md) |
| CIDR·서브넷 | 주소의 공통 비트를 표시하는 방식과 나눈 네트워크 대역이다. /24는 앞 24비트가 공통이다 | [05](05-routing-and-access.md) |
| 방화벽 | 조건에 맞는 통신을 허용하거나 차단한다. 경로를 정하는 것과 다른 역할이다 | [05](05-routing-and-access.md) |
| NAT | 경계에서 주소·포트를 변환한다. 본문의 예에서는 연결 대응을 기억해 외부 응답을 안으로 돌린다 | [05](05-routing-and-access.md) |
| 프록시 | 중간에서 요청을 받아 다른 서버로 전달하는 역할이다. 앞뒤 연결은 별도일 수 있다 | [05](05-routing-and-access.md) |

## 3. 실행 환경 — 템플릿과 실제 실행, 남겨야 할 데이터를 나눈다

같은 프로그램을 옮기려면 의존 파일과 실행 조건도 필요하다. 이미지를 고정해도 실행 중 메모리·파일·설정은 구분해 관리한다.

| 용어 | 뜻과 작동의 연결 | 다시 읽을 곳 |
|---|---|---|
| 런타임·의존성 | 앱을 실행하는 데 필요한 소프트웨어와 앱이 기대는 외부 기능 묶음이다 | [07](07-containers-and-images.md) |
| 이미지·컨테이너 | 실행 파일 등의 템플릿과 거기서 만든 격리된 실행 인스턴스다 | [07](07-containers-and-images.md) |
| 커널·VM | 운영체제의 핵심 부분과 가상 하드웨어 위에 게스트 운영체제를 실행하는 방식이다 | [07](07-containers-and-images.md) |
| 네임스페이스·cgroup | 보이는 자원의 범위를 나누는 기능과 자원 사용을 관리·제한하는 기능이다 | [07](07-containers-and-images.md) |
| 쓰기 계층·볼륨 | 컨테이너에 종속된 파일 변경과 별도 수명으로 붙일 수 있는 저장 공간을 구분한다 | [07](07-containers-and-images.md) |
| 마운트 | 저장 공간을 사용할 경로에 연결하는 일이다. 경로와 실제 저장 공간의 수명은 다를 수 있다 | [07](07-containers-and-images.md) |
| 환경변수 | 실행 시 이름·값으로 공급하는 설정이다. 같은 이미지도 다른 설정으로 실행할 수 있다 | [07](07-containers-and-images.md) |
| 태그·다이제스트 | 바뀔 수 있는 이미지 이름표와 콘텐츠 식별자다. 실제 실행 산출물을 구별할 때 사용한다 | [07](07-containers-and-images.md) |

## 4. 데이터 — 보관하고 찾고 함께 바꾼다

업무 사실을 영속 저장한 뒤 질의로 찾는다. 여러 변경과 여러 실행자가 얽히면 원자성과 격리가 필요해진다. 현재 상태의 복제와 과거 상태 복구도 나눈다.

| 용어 | 뜻과 작동의 연결 | 다시 읽을 곳 |
|---|---|---|
| 영속성·파일시스템 | 실행 뒤에도 데이터를 유지하는 성질과 파일·폴더 등을 저장 장치 위에서 관리하는 체계다 | [08](08-storage-and-databases.md) |
| DB·테이블·스키마 | 데이터 관리 체계, 행과 열의 표, 그 구조와 규칙이다. 단순 저장 파일과 관리 기능을 구분한다 | [08](08-storage-and-databases.md) |
| 질의·SQL | 데이터를 읽거나 바꾸는 요청과 이를 표현하는 언어다 | [08](08-storage-and-databases.md) |
| 기본키·인덱스 | 행을 유일하게 식별하는 기준과 데이터를 찾기 위한 별도 자료구조다 | [08](08-storage-and-databases.md) |
| 블록·객체 저장소 | 장치처럼 블록을 제공하는 저장소와 키로 객체를 저장·읽는 저장소다. DB 기능과 같은 층은 아니다 | [08](08-storage-and-databases.md) |
| 연결 풀 | 연결을 빌려주고 반환받아 재사용하는 모음이다. 빌릴 차례 대기와 실제 질의 시간을 나눈다 | [08](08-storage-and-databases.md) |
| 트랜잭션·원자성 | 함께 다룰 변경 단위와 그 변경을 전부 반영하거나 취소하는 성질이다 | [09](09-transactions-and-recovery.md) |
| 커밋·롤백 | 변경 단위를 확정하거나 취소하는 일이다. 내 DB 밖의 결제가 자동 취소되는 것은 아니다 | [09](09-transactions-and-recovery.md) |
| 잠금·격리 | 동시 작업의 접근 순서와 간섭을 조정하는 수단·약속이다 | [09](09-transactions-and-recovery.md) |
| 복제·백업·RPO·RTO | 현재 상태의 다른 사본, 복구용 데이터, 허용 손실 시간, 복구 시간 목표를 구분한다 | [09](09-transactions-and-recovery.md) |

## 5. 협력과 변경 — 다음 요청과 다음 버전으로 이어 간다

앱을 늘리면 특정 실행 인스턴스의 메모리에 묶이지 않아야 한다. 답을 못 받으면 결과가 불확실하고, 나중에 할 일은 재전달될 수 있다. 새 버전도 옛 버전과 잠시 함께 작동한다.

| 용어 | 뜻과 작동의 연결 | 다시 읽을 곳 |
|---|---|---|
| 부하 분산 | 여러 대상으로 요청과 일을 나누는 역할이다. 메모리를 공유해 주는 기능은 아니다 | [10](10-scaling-and-state.md) |
| 세션·쿠키 | 사용자와 이어지는 상태·식별 정보를 관리하는 방법과 브라우저의 값 보관·전송 기능이다 | [10](10-scaling-and-state.md) |
| 무상태 앱 | 다음 요청이 특정 인스턴스의 이전 요청 메모리에 꼭 묶이지 않도록 만든 앱이다 | [10](10-scaling-and-state.md) |
| 타임아웃·재시도 | 기다림 한도와 같은 작업 의도의 반복이다. 상대의 미처리를 증명하는 것은 아니다 | [11](11-timeouts-and-retries.md) |
| 백오프·지터 | 시도 간 대기를 늘리는 것과 시점을 흩뜨리는 것이다. 중복 효과 방지는 별도다 | [11](11-timeouts-and-retries.md) |
| 멱등성 | 같은 의도를 반복해도 추가 업무 효과를 만들지 않는 성질이다. 키의 동시 처리까지 다룬다 | [11](11-timeouts-and-retries.md) |
| 캐시·무효화 | 원본 결과를 재사용하는 저장과 오래된 결과를 더는 쓰지 않도록 만드는 처리다 | [12](12-caches-and-queues.md) |
| 큐·소비자·ack | 작업 보관 수단, 작업 처리자, 완료 확인이다. 처리 후 확인 전에 죽으면 재전달될 수 있다 | [12](12-caches-and-queues.md) |
| 빌드·배포 | 실행 산출물을 만드는 과정과 그것을 실행 환경에 적용하는 과정이다 | [13](13-deployment-and-shutdown.md) |
| 준비됨·드레이닝 | 새 요청을 받을 수 있는 상태와 새 배정을 멈추며 기존 일을 마무리하는 과정이다 | [13](13-deployment-and-shutdown.md) |
| 마이그레이션·백필 | 구조·데이터의 전환과 기존 데이터를 새 형식으로 채우는 작업이다. 실시간 쓰기와 충돌할 수 있다 | [14](14-schema-and-rollback.md) |
| 호환성·롤백 | 서로 다른 형식이 함께 작동할 관계와 변경을 되돌리는 절차다. 지원할 이전 버전을 구체화한다 | [14](14-schema-and-rollback.md) |

## 6. 운영 판단과 플랫폼 — 관측하고 허용하고 역할을 배치한다

관측은 사용자의 결과를 증거로 만든다. 권한은 요청 주체와 허용 작업을 나눈다. AWS 서비스는 그 위의 실행·통신·저장 역할을 제공한다.

| 용어 | 뜻과 작동의 연결 | 다시 읽을 곳 |
|---|---|---|
| 로그·메트릭·추적 | 사건 기록, 집계 수치, 한 요청의 작업 구간 연결이다. 질문에 따라 증거를 고른다 | [15](15-observability-and-capacity.md) |
| 분위수 | 관측값을 정렬해 특정 위치의 값을 읽는 방법이다. 평균이 감춘 긴 지연을 볼 수 있다 | [15](15-observability-and-capacity.md) |
| 처리량·체류 시간·진행 중 수 | 단위 시간 완료 수, 시스템 안에 머문 시간, 아직 끝나지 않은 수를 구분한다 | [15](15-observability-and-capacity.md) |
| SLI·SLO | 서비스 수준을 측정할 지표와 그 목표다. 분모와 측정 기간도 정한다 | [15](15-observability-and-capacity.md) |
