## A. 수치와 계산 (5장)

### 카드 1 — KV 캐시 크기 공식 `[03]`

```
KV 캐시 = 2 × L × n_kv × head_dim × s × b × bytes
          ↑   ↑     ↑        ↑       ↑   ↑    ↑
        K와V 레이어 KV헤드  헤드차원 길이 배치 정밀도
```

**`× L`을 빼먹는 것이 가장 흔한 실수** — 어텐션은 레이어마다 독립이므로 레이어 수만큼 곱해집니다.
**왜 암기**: 모델 구성값만 보고 "이 컨텍스트를 이 GPU에서 감당하나"를 판단하는 유일한 도구.

### 카드 2 — Llama 3.1 70B 실측 규모 `[03]`

| 항목 | 값 |
|---|---|
| 구성 | L=80, n_kv=8, head_dim=128, fp16 |
| **토큰 1개당** | **320 KB** |
| 8K 컨텍스트, 배치 1 | 2.5 GB |
| 128K 컨텍스트, 배치 1 | 40 GB |
| 8K 컨텍스트, 배치 16 | 40 GB (위와 동일) |
| MHA였다면 (n_kv=64) | 128K에서 약 320 GB |

**왜 암기**: 규모 감각의 기준점. `s`와 `b`가 같은 예산을 나눠 쓴다는 것을 마지막 두 줄이 보여줍니다.

### 카드 3 — 캐시 가격 배수와 손익분기 `[06]`

| 동작 | 배수 |
|---|---|
| 캐시 읽기 | **0.1×** |
| 캐시 쓰기 (5분 TTL) | **1.25×** |
| 캐시 쓰기 (1시간 TTL) | **2×** |

```
5분 TTL:   1.25 + 0.1 = 1.35×  vs  미사용 2×    → 2회면 이득
1시간 TTL: 2 + 0.1 + 0.1 = 2.2× vs  미사용 3×   → 3회 이상 필요
```

**왜 암기**: TTL 선택의 유일한 정량 근거. 1시간 TTL은 공짜가 아닙니다.

### 카드 4 — 최소 캐시 가능 토큰 (⚠️ 비단조) `[06]`

| 모델 | 최소 |
|---|---:|
| Opus 5, Fable 5, Mythos 5 | **512** |
| Opus 4.8, Sonnet 5, Sonnet 4.6/4.5, Opus 4.1/4, Sonnet 4 | 1,024 |
| Opus 4.7, Mythos Preview, Haiku 3.5 | 2,048 |
| **Opus 4.6, Opus 4.5, Haiku 4.5** | **4,096** |

**세대가 올라간다고 작아지지 않습니다.** 미달 시 **에러 없이 조용히** 캐시되지 않습니다.
**왜 암기**: 모델 교체로 캐시가 꺼지는 사고를 막는 유일한 방어. 특히 Haiku 4.5는 저비용인데 최소값이 가장 큽니다.

### 카드 5 — 출력 토큰은 입력의 약 5배 `[05]`

Claude 전 모델 공통 비율 (Opus 5: $5→$25, Sonnet 5: $3→$15, Haiku 4.5: $1→$5).

**왜 암기**: 프롬프트를 늘려 응답을 줄이는 것이 순이익인 판단 근거. 에이전트 루프에서 턴 수만큼 곱해집니다.

## B. 불변 트레이드오프 (6장)

### 카드 6 — 네 원리의 순환 `[02]`

```
① 축적 → ② 접기 → ③ 스냅샷 → ④ 축출 → (①로)
```

앞이 뒤를 **필연적으로** 요구합니다. 어떤 시스템의 상태 설계에서 빠진 원리를 찾는 체크리스트.

**함께**: 상태는 파생물이고 **로그가 진실 원천**이다. / **안정적인 것을 앞에, 변동하는 것을 뒤에** (세 지층 공통 배치 규율).

### 카드 7 — 캐시 메모리는 선형, 어텐션 연산은 제곱 `[03]`

| | 스텝당 | 전체 (N개 생성) |
|---|---|---|
| 캐시 없음 | `O(n²·d)` | `O(N³·d)` |
| 캐시 있음 | `O(n·d)` | `O(N²·d)` |

캐시가 없애는 것은 **재계산**뿐, 남은 제곱은 볼 대상을 줄여야(SWA) 사라집니다.
**왜 암기**: 병목이 메모리인지 연산인지 가르는 근본 원인.

### 카드 8 — prefill과 decode의 성격 `[05]`

| | 처리 | 병목 |
|---|---|---|
| **prefill** | 프롬프트 전체 병렬 (행렬×행렬) | **연산** (compute-bound) |
| **decode** | 토큰 1개씩 순차 (행렬×벡터) | **메모리 대역폭** (memory-bound) |

decode는 매 토큰마다 **모델 가중치 전체 + 해당 시퀀스 KV 캐시 전체**를 읽습니다.
**왜 암기**: 컨텍스트가 길어지면 왜 토큰 생성이 느려지는지의 유일한 설명.

### 카드 9 — 배칭: 가중치는 공유, KV는 안 됨 `[05]`

```
가중치:  모든 요청 공유    → 배칭으로 읽기 비용 분산 ✅
KV 캐시: 요청마다 별개     → 배칭해도 읽는 양 비례 증가 ❌
```

**왜 암기**: 배칭 수익의 한계이자 "긴 컨텍스트 vs 동시 처리량" 트레이드오프의 물리적 정체.

### 카드 10 — SWA 유효 시야와 간접 전파의 손실 `[07]`

```
유효 시야 ≈ W × L      (Mistral 7B: 4096 × 32 ≈ 131K)
```

간접 전파는 **손실이 있습니다** — (a) 압축 누적, (b) **지목 불가**.

| ✅ 견딤 | ❌ 취약 |
|---|---|
| 대화 지속, 요약, 전반적 판단 | 정확한 인용, needle-in-haystack, N번째 항목 회수 |

**왜 암기**: RAG·인용 워크로드에서 모델을 고르는 결정 기준.

### 카드 11 — 절감 기법: 학습 시점 vs 런타임 `[04]`

| 학습 시점 결정 (바꿀 수 없음) | 런타임 결정 (튜닝 가능) |
|---|---|
| GQA / MQA / MLA, 크로스레이어 공유, SWA | 접두사 공유, KV 양자화, PagedAttention, 오프로드 |
| → **모델 선택의 기준** | → **운영의 조정 손잡이** |

**함께**: GQA는 `n_kv`를 줄인 비율만큼 캐시를 줄입니다 (Llama 3.1 70B: 64/8 = 8배).
**왜 암기**: 잘못 분류하면 없는 손잡이를 찾게 됩니다. "캐시 부족"에 GQA를 켤 수는 없습니다.

## C. 진단 신호 (5장)

### 카드 12 — TTFT는 prefill, TPOT는 decode `[05]`

| 증상 | 진단 | 처방 |
|---|---|---|
| TTFT 길고 TPOT 정상 | prefill | 프롬프트 캐싱, 프롬프트 단축, chunked prefill |
| TTFT 정상, TPOT 길다 | decode | KV 양자화, 컨텍스트 단축, 배치 조정 |
| 둘 다 나쁘고 부하 높음 | 용량 | HBM 증설, 배치 정책, 모델 교체 |
| TTFT가 요청마다 튄다 | 큐 대기 / 캐시 적중 편차 | 캐시 적중률 확인 |

**⭐ 프롬프트 캐싱은 TTFT만 개선합니다.** TPOT 문제에 캐싱을 붙이면 효과가 없습니다.

### 카드 13 — `cache_read_input_tokens`가 계속 0 `[06]`

**조용한 무효화자가 작동 중**입니다. 후보:

`datetime.now()` / `uuid4()` in 시스템 프롬프트 · `json.dumps()` sort_keys 없음 · set 순회 · 세션·유저 ID 보간 · 조건부 system 섹션 · 유저별 도구 목록

```
전체 프롬프트 = input_tokens + cache_creation_input_tokens + cache_read_input_tokens
```
`input_tokens`는 **캐시되지 않은 나머지**일 뿐 — 단일 필드가 아니라 합을 봅니다.

### 카드 14 — 렌더 순서와 무효화 계층 `[06]`

```
tools → system → messages     (tools는 위치 0)
```

| 전면 무효화 | 캐시 유지 |
|---|---|
| **도구 정의 변경, 모델 교체** | `tool_choice`, thinking on/off, 이미지, 메시지 추가 |

**우회로**: 시스템 프롬프트를 중간에 바꿔야 하면 `messages[]`에 `{"role": "system", ...}` **append** (Opus 5/4.8/Fable 5/Mythos 5, 베타 헤더 불필요). 모델 교체에는 우회로가 없으므로 서브에이전트로 분리합니다.

### 카드 15 — 브레이크포인트·마커·되돌아보기 `[06]`

- 요청당 **최대 4개** 브레이크포인트
- 마커는 **"공유되는 구간의 끝"** 에 둡니다 (전체 프롬프트의 끝이 아님)
- **20블록 되돌아보기 창** — 한 턴이 20블록을 넘으면 조용히 미적중 (도구 호출이 많은 루프에서 흔함)
- 동시 요청은 서로의 캐시를 읽을 수 없음 → 1개 보내고 **첫 토큰 스트리밍 후** 나머지 발사

### 카드 16 — 앞부터 축출하면 perplexity 10~100배 급등 `[07]`

원인은 의미가 아니라 **softmax의 "합이 1" 제약**입니다. 모델은 볼 게 없을 때도 비중을 배출해야 하고, 그 배출구를 맨 앞 토큰에 만듭니다 = **attention sink**.

**처방: 앞 4개 토큰을 영구 고정** + 최근 W개 슬라이딩. 이 방식으로 최대 400만 토큰까지 안정 동작.

**왜 암기**: "의미 없는 토큰"이라며 제거하는 최적화가 시스템을 깨뜨립니다.

## D. 의사결정 경계 (4장)

### 카드 17 — 하이브리드 어텐션 구성값 `[07]`

| 모델 | local : global | local 창 |
|---|---|---|
| Gemma 2 | 1 : 1 (교대) | 4,096 |
| **Gemma 3** | **5 : 1** | **1,024** |

```
32K 기준 KV 오버헤드:  global-only 60%  →  Gemma 3 하이브리드 15% 미만
```

방향(local 비중↑, 창↓)이 업계 추세입니다. 품질 영향은 ablation에서 미미하다고 보고.

**선택**: 무한 스트림 → 순수 SWA+sink / 짧고 정확 → full / **긴 컨텍스트 + 회수 정확도 → 하이브리드(기본)**

### 카드 18 — 스냅샷 vs 축출: 원본 보관 여부 `[02][09]`

| 원본 처리 | 정체 | 되돌릴 수 있나 |
|---|---|---|
| 보관 | **스냅샷** | ✅ |
| 버림 | **축출** | ❌ |

**철칙**: 스냅샷을 전부 지워도 시스템은 **느려질 뿐 틀리지 않습니다.** 이 성질을 잃으면 스냅샷이 아닙니다.

**함께**: 스냅샷에서 스냅샷을 만들면 오차가 누적됩니다 → 항상 **로그에서** 만들고, 연쇄가 불가피하면 카운터 상한을 둡니다.

### 카드 19 — 에이전트의 앵커 `[09]`

**축출 대상에서 제외해야 하는 것**: 시스템 프롬프트 / 도구 정의 / 원래 과업 목표 / 확정된 제약·결정

| 버리면 | 증상 |
|---|---|
| 시스템 프롬프트 | 페르소나 붕괴, 지시 위반 |
| 도구 정의 | 도구 오사용, 없는 도구 호출 |
| 과업 목표 | 목표 표류 |
| 확정 제약 | 배제한 방향 재시도 |

```
[고정: 앵커]  [축출 대상: 오래된 원시 도구 출력]  [고정: 최근 N턴]
```
이 구조가 카드 14의 캐시 배치와 **일치**합니다 — 두 요구가 같은 방향입니다.

### 카드 20 — 에이전트 재생 규율 (4개 묶음) `[08][09]`

1. **비멱등 도구**(메일·결제·PR)는 재생 시 **반드시 캐시된 결과**를 씁니다. 근본 해법은 도구 입력에 **멱등 키**를 넣는 것.
2. **비결정적 값**(`now()`, `random()`)은 실행 중 생성하지 말고 **주입**합니다 — 안 그러면 resume이 다른 결과를 냅니다.
3. **실패는 지우지 말고 append** — 에러 결과를 `is_error: true`로 남깁니다. 지우면 캐시가 깨지고 모델이 같은 실패를 반복합니다.
4. **버리기 전에 파일로 쓸 수 있는지 확인** — 오프로드(되돌림 가능) > 축출(불가).

**함께**: 도메인/에이전트 로직은 **실행 컨텍스트(실제인가 재생인가)를 몰라야** 합니다. 판단은 게이트웨이가 합니다.

## 진단 신호 요약표 (한 장 요약)

| 증상 | 가장 가능성 높은 원인 | 근거 |
|---|---|---|
| 첫 응답이 느리다 | prefill — 프롬프트 길이 / 캐시 미적중 | 카드 12 |
| 응답이 천천히 흘러나온다 | decode — KV 캐시 크기 / 대역폭 포화 | 카드 8, 12 |
| 캐시 적중률 0 | 프리픽스의 조용한 무효화자 | 카드 13 |
| 모델 교체 후 비용 상승 | 최소 캐시 토큰 미달로 캐싱 꺼짐 | 카드 4 |
| 도구 루프가 길어지면 적중률 하락 | 20블록 되돌아보기 창 초과 | 카드 15 |
| 긴 문서에서 인용이 틀린다 | SWA 간접 전파 — 지목 불가 | 카드 10, 17 |

| 이벤트 이름이 `XxxUpdated`뿐 | CRUD를 이벤트로 위장 | `[08]` |
