# 파트 1. 회수 연습 (자료를 덮고)

> 정답: [93-solutions.md](93-solutions.md) § 파트 1

**1-1.** KV 캐시 크기 공식의 7개 항을 순서대로 쓰고, 가장 자주 빠뜨리는 항이 무엇이며 왜 필요한지 설명하라.

**1-4.** 최소 캐시 가능 토큰이 "비단조적"이라는 말의 의미를 설명하고, 3,000토큰 프롬프트가 캐시되지 않는 모델을 두 개 이상 들라.

**1-5.** Claude 모델의 출력 토큰 단가는 입력의 몇 배이고, 그 비대칭의 물리적 원인은 무엇인가?

**1-7.** 캐시 유무에 따른 스텝당·전체 시간복잡도를 각각 쓰고, 캐시가 없애지 **못하는** 것이 무엇인지 설명하라.

**1-8.** prefill과 decode의 병목을 각각 쓰고, decode가 매 토큰마다 메모리에서 읽는 것 두 가지를 들라.

**1-14.** 프롬프트 렌더 순서를 쓰고, 캐시를 **전면 무효화**하는 변경 두 가지와 그 중 하나의 우회로를 설명하라.

**1-16.** 오래된 KV를 앞에서부터 버렸을 때 관측되는 현상과 그 원인을 쓰고, 표준 처방을 설명하라.

**1-17.** Gemma 2와 Gemma 3의 하이브리드 구성값을 쓰고, 변화의 방향과 그 효과를 설명하라.

# 파트 2. 판단 문제 (시나리오)

> 해설: [93-solutions.md](93-solutions.md) § 파트 2

각 문항에서 **선택과 근거**를 쓰고, 명시된 경우 **반대 선택이 나은 조건**도 함께 적으세요.

**2-1.** 사내 문서 QA 서비스를 만든다. 시스템 프롬프트 + 사내 용어집이 3,500토큰이고, 사용자 질문은 평균 40토큰이다. 트래픽은 업무시간에 분당 5~10건, 야간에는 거의 없다.

캐싱 전략을 정하라 — 브레이크포인트 위치, TTL, 그리고 이 프롬프트에서 쓰면 **안 되는** 모델이 있는지. 반대 선택(다른 TTL)이 나은 조건도 적으라.

**2-2.** 100페이지 계약서를 검토하는 에이전트를 만든다. 사용자는 (a) 전반적 위험 요약, (b) 특정 조항의 정확한 문구 인용을 모두 요구한다.

후보 모델 A는 full attention, 후보 B는 5:1 하이브리드(local 1024)다. 어느 쪽을 고르고 왜인가? 반대 선택이 나은 조건도 적으라.

**2-3.** 에이전트가 20턴째에서 컨텍스트 한계에 도달했다. 두 가지 처방이 제안되었다.

(가) 오래된 도구 결과의 원시 출력을 컨텍스트에서 제거
(나) 전체 이력을 요약해 새 컨텍스트로 재시작

각각의 정체를 02의 원리로 분류하고, 어느 것을 먼저 시도할지 근거와 함께 답하라.

**2-4.** 배포 파이프라인 에이전트가 `create_pull_request` 도구를 호출한 직후 프로세스가 죽었다. 로그에는 `tool_use`가 남아 있지만 `tool_result`는 없다.

재시작 전략을 설계하라. 어떤 정보가 필요하고, 도구 프로토콜을 어떻게 고쳐야 재발을 막을 수 있는가?

**2-5.** 팀이 정산 시스템에 이벤트 소싱을 도입했다. 6개월 후 다음 증상이 보고된다.

- 조회 API가 느리다 (특정 계정의 잔액 조회에 3초)
- 스테이징에서 이벤트를 재생하면 실운영 고객에게 알림이 발송된다
- 이벤트 이름이 대부분 `SettlementUpdated`, `AccountChanged`다

각 증상을 진단하고 처방하라. 어느 것이 가장 시급한가?

**2-6.** 하네스에 "매 요청마다 현재 시각과 활성 모드를 시스템 프롬프트 상단에 삽입"하는 코드가 있다. 캐시 적중률이 0이다.

세 가지 수정안을 비교하고, 어떤 조건에서 각각이 최선인지 답하라.

(가) 시각·모드를 `messages` 마지막에 텍스트로 넣는다
(나) `messages`에 `{"role": "system", ...}` 메시지로 append한다
(다) 시각을 아예 제거하고 필요할 때 도구로 조회하게 한다

# 파트 3. 재현 과제 (직접 만들기)

> 테스트: [93-solutions.md](93-solutions.md) § 파트 3

**정답 대신 테스트를 받습니다.** 참고 구현 골격은 주지 않습니다 — 읽으면 베끼게 되니까요. 대신 각 과제마다 **당신의 구현을 돌려 판정하는 테스트**가 93에 있습니다. 아래 성공 기준이 그 테스트의 검사 항목과 1:1 대응합니다.

그래서 순서는 이렇습니다: **① 인터페이스대로 구현 → ② 93의 테스트를 저장해 실행 → ③ 실패 항목을 보고 고침.** 막히면 테스트 코드가 아니라 "막히면" 항목의 학습 파일로 돌아가세요.

예시는 Python이지만 다른 언어로 풀어도 됩니다 — 같은 판정 항목을 그 언어로 옮기면 됩니다.

---

**3-1.** KV 캐시 계산기를 작성하라. 모델 구성값을 받아 캐시 크기를 계산하고, 주어진 GPU 메모리에서 가능한 (컨텍스트 길이 × 배치) 조합을 출력한다.

- 구현할 인터페이스 (내부 구조는 자유)
  - `bytes_per_token(layers, n_kv, head_dim, dtype_bytes=2) -> int`
  - `feasible_combos(available_bytes, bpt, candidates) -> 반복 가능한 (s, b) 쌍`
  - 파일명 `kv_calc.py`
- 성공 기준
  - [ ] `L`, `n_kv`, `head_dim`, dtype을 입력받아 **토큰당 바이트**를 계산한다
  - [ ] Llama 3.1 70B(80/8/128/fp16)에 대해 **320 KB**(327,680바이트)가 나온다
  - [ ] dtype 항이 실제로 작동한다 (fp8이면 절반)
  - [ ] 사용 가능 메모리를 받아 `(s, b)` 조합을 최소 3개 산출한다
  - [ ] 40GB에서 8K→배치 16, 128K→배치 1이 나온다
  - [ ] MHA 가정(`n_kv` = Query 헤드 수)이 GQA의 정확히 8배로 나온다
- 소요 예상: 20~30분
- 막히면: `03-kv-cache.md` § 필수 지식 2

**3-2.** 슬라이딩 윈도우 + attention sink의 **마스크 생성기**를 작성하라. 실제 어텐션 계산은 필요 없고, 어떤 위치가 보이는지만 판정한다.

- 구현할 인터페이스
  - `visible(i, j, W, n_sink=0) -> bool`
  - `render(n, W, n_sink=0) -> None` (마스크를 표준출력에 그림)
  - 파일명 `swa_mask.py`
- 성공 기준
  - [ ] `(i, j, W, n_sink)`를 받아 `bool`을 반환한다
  - [ ] causal 조건이 반영돼 있다 (`j > i`면 차단, `j == i`는 보임)
  - [ ] 창 조건이 **경계까지 정확**하다 (`i − W < j`이지 `i − W ≤ j`가 아니다)
  - [ ] **sink 예외**가 반영돼 있다 (`j < n_sink`면 창을 벗어나도 보임)
  - [ ] sink가 causal을 뚫지 않는다 (미래 토큰이 sink라도 못 봄)
  - [ ] `W=4, n_sink=2, n=10` 렌더링에서 왼쪽 2열이 세로로 채워진다
- 소요 예상: 20분
- 막히면: `07-sliding-window.md` § 필수 지식 1

**3-3.** 프롬프트 캐시 **프리픽스 안정성 검사기**를 작성하라. 같은 논리적 요청을 두 번 만들었을 때 프리픽스가 바이트 단위로 같은지 판정한다.

- 구현할 인터페이스
  - `render_prefix(tools, system, messages) -> str` (렌더 순서 `tools → system → messages`)
  - `compare(req_a, req_b) -> dict` — 최소한 `same: bool`, 다를 때 `offset: int`를 담는다
  - 각 `req`는 `{"tools": …, "system": …, "messages": …}` 형태
  - 파일명 `prefix_check.py`
- 성공 기준
  - [ ] 렌더 순서가 `tools → system → messages`다 (tools가 위치 0)
  - [ ] 동일 입력이면 `same=True`
  - [ ] 다르면 `same=False`이고 **처음 갈라지는 오프셋**을 정수로 보고한다
  - [ ] 그 오프셋이 실제로 바뀐 구간을 가리킨다
  - [ ] 시스템 프롬프트에 `now()`가 들어가면 두 번 만든 요청을 **불안정으로 판정**한다
  - [ ] 도구 목록의 **순서만** 바꿔도 불안정으로 판정한다
- 소요 예상: 25~35분
- 막히면: `06-prompt-caching.md` § 필수 지식 1~2
